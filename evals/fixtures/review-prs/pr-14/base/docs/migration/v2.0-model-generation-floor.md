# Migration guide — v2.0.0-rc.1 "Model-generation floor" (release candidate)

**Audience:** operators and downstream tooling upgrading from any v1.19x / v1.20x
release. **Status:** release candidate — soak it, report against the `2.0.0-rc`
label, expect `-rc.N` fixes before `2.0.0`. **TL;DR:** the framework's own use
of Claude moves to the Opus 5 / Sonnet 5 / Fable 5.1 generation, several
defaults change on the Anthropic wire, two dead config keys are removed, three
protocols are archived, NOTES.md gains a size fence, Aleph becomes opt-in, and
the post-merge pipeline prepares candidates instead of publishing. Every
default change has a kill switch; every removal has a compat path. The
line-by-line evidence is in
`grimoires/loa/reports/breaking-surface-audit-2.0.0-rc.1.md`.

| Old way | New way | Switch back |
|---|---|---|
| Every cheval hop capped at 4096 output tokens; `--max-tokens 0` meant 4096 | Anthropic hops default to 16K (non-streaming) / 64K (streaming), clamped to the catalog; `--max-tokens 0` is refused | `LOA_CHEVAL_LEGACY_WIRE=1`, or an explicit `--max-tokens N` |
| No `thinking` on the wire | `thinking: {type: adaptive}` on Opus 5 / 4.8 / 4.7 / 4.6 and Sonnet 5 / 4.6 (never on Fable) | `LOA_CHEVAL_LEGACY_WIRE=1` |
| `opus` → `claude-opus-4-8`, `fable` → `claude-fable-5` | `opus` → `claude-opus-5`, `fable` → `claude-fable-5-1` | pin the explicit id in `.loa.config.yaml` |
| `tool_choice: required` silently became `any` | raises `InvalidInputError` | send `auto`, `none` or a named tool |
| `flatline_protocol.dissent.repair_loop`, top-level `effort:` | keys removed (repair loop always on for unenforced voices; effort from SKILL.md frontmatter / `--effort`) | delete the keys — a stale key is ignored |
| Cost ledger at `grimoires/loa/a2a/cost-ledger.jsonl` | `.run/cost-ledger.jsonl`; `LOA_COST_LEDGER_PATH` overrides; writer refuses symlinks | `--ledger <old path>` on the readers |
| `.claude/protocols/{risk-analysis,sprint-completion,upgrade-process}.md` | archived under `grimoires/loa/archive/protocols/` | read from the archive path |
| Unbounded NOTES.md | 200 KiB block line on growth; recovery reads a ≤ 68 KiB slice | `notes-guard.sh rotate`; `read --full` |
| Aleph refreshed/verified whenever present | `aleph.enabled: false` unless you say otherwise | `aleph.enabled: true` |
| Merge → tag → GitHub release | merge → candidate artifact → `--publish … --approve-sha256` | none (by design) |

## 1. What changed and why

Cycle-124 (PR #1266, sprints 235–238) is the "model-generation floor": the
catalog, the adapters and the dispatchers now assume the current Claude
generation — 1M context, 128K output, adaptive thinking, prompt caching,
structured outputs — and the budgets, gates and prompts were re-sized to match
(prompt byte budgets, coverage-first review/audit, bounded NOTES.md, ledger
isolation, an eval A/B harness that measured the prompt diet). Two decisions
sit on top: **Aleph is opt-in** (a third-party component must never turn a Loa
gate red) and **the 2.0 line ships as a release candidate first** (the defaults
above are felt immediately by every downstream mount, so they get a soak window).
Rationale and alternatives: `docs/architecture/ADR-004-model-generation-floor.md`.

## 2. Migration recipes

### Recipe A — a downstream mount upgrading from v1.19x / v1.20x

1. Read the CHANGELOG `[2.0.0-rc.1]` **Breaking** list once.
2. Upgrade to the candidate: `/update-loa` (or re-run the installer with
   `--tag v2.0.0-rc.1`). `.loa-version.json` and the `CLAUDE.loa.md` header read
   `2.0.0-rc.1`.
3. Clean your `.loa.config.yaml`: delete `flatline_protocol.dissent.repair_loop`
   and any top-level `effort:` block (both are ignored, neither errors). If you
   pinned `hounfour.models.opus` yourself, your value still wins.
4. If you keep cost history, note the new default ledger path (`.run/cost-ledger.jsonl`);
   run `cost-report.sh --ledger grimoires/loa/a2a/cost-ledger.jsonl` for the old file.
5. Run the validation block in §5. Nothing else is required.

### Recipe B — a repository that relies on Aleph

Aleph is no longer refreshed, verified, tested or synced unless you opt in
(`.claude/scripts/lib/aleph-opt-in.sh`; call sites in `mount-submodule.sh`,
`update-loa.sh`, `check-loa.sh`, the three `tests/unit/aleph-*.bats` suites and
both Aleph workflows).

```yaml
# .loa.config.yaml — add BEFORE upgrading so /update-loa keeps refreshing the tree
aleph:
  enabled: true
```

CI matrices use `LOA_ALEPH_ENABLED=1`. With the key set the behaviour is
byte-identical to v1.202.1. Without it: `/update-loa` leaves the installed
Aleph tree as it is, `check-loa.sh` prints `Aleph: opt-in disabled … skipped`,
the Aleph suites skip themselves, and the nightly release-sync stops proposing
bumps. The fate of the vendored tree itself is tracked as bead `bd-c7ma`.

### Recipe C — a repository with pinned `max_tokens` or `tool_choice`

- **Wrappers passing `--max-tokens 0`** now get `--max-tokens must be a positive
  integer (got 0); omit it for the per-model default` (exit 2). Remove the flag,
  or pass the budget you mean; values above the catalog `max_output_tokens` are
  clamped with a logged warning, never raised.
- **Cost ceilings that assumed 4096-token outputs**: Anthropic hops may now
  produce up to 16K (non-streaming) or 64K (streaming) tokens. Set explicit
  budgets where spend matters, or export `LOA_CHEVAL_LEGACY_WIRE=1` to keep the
  old 4096 default, the old body without `thinking`, `cache_control` or
  `output_config.format` — all three come back together.
- **`tool_choice: required` (or any unknown mode)** raises on the Anthropic
  adapter. Use `auto`, `none`, or a specific tool.
- **Old model generation**: pin `anthropic:claude-opus-4-8` (or `-4-7`) in
  `.loa.config.yaml`; the ids remain in the catalog. Do not rely on
  `LOA_FORCE_LEGACY_ALIASES` for this — its snapshot predates 2.0.

### Recipe D — a repository that consumes the archived protocols or grades on verdict prose

- `risk-analysis.md`, `sprint-completion.md` and `upgrade-process.md` moved
  unchanged to `grimoires/loa/archive/protocols/`; any override, hook or script
  that reads them under `.claude/protocols/` gets ENOENT. Re-point the path. The
  verdict-trailer rule they carried now lives in `feedback-loops.md`.
- The golden path (`golden-path.sh`) parses every feedback file that carries a
  `LOA-VERDICT` marker through `verdict-derive.sh`: prose and trailer must
  agree, `critical + high > 0` forces `CHANGES_REQUIRED`, a lowercase or
  malformed marker is a violation, and the audit gate re-checks the review's
  `excluded` count. **Legacy files with no trailer keep the prose heuristic.**
  To repair a sprint that stopped counting as reviewed:
  `.claude/scripts/verdict-derive.sh --file grimoires/loa/a2a/sprint-N/engineer-feedback.md --gate review`
  prints the exact inconsistency.
- Review/audit prompts no longer ask for a minimum number of findings; a
  downstream grader that counted `### Concerns Identified (minimum 3)` headings
  should count `file:line`-cited findings instead.

### Recipe E — operators of the eval harness and the cost ledger

- `evals/harness/execute-agent.sh` runs the agent under test with
  `--restricted --tools Read,Grep,Glob,Write`: your user/project/local settings
  are ignored, Bash is unavailable, file tools are confined to the sandbox, and
  `GH_TOKEN` / `GITHUB_TOKEN` / `OPENAI_API_KEY` / `AWS_*` are unset. Tasks that
  need Bash fail by design; there is no override flag. Graders run
  agent-authored test commands under `env -i`.
- Every harness (pytest, bats, TS) exports `LOA_MODELINV_LOG_PATH` and
  `LOA_COST_LEDGER_PATH` into its tmpdir; `tools/check-ledger-hygiene.sh` in CI
  fails if a run wrote the production ledgers. If you have your own harness,
  export the two variables before it spawns cheval.
- The MODELINV payload schema gained optional fields (`tokens_cache_read`,
  `tokens_cache_creation`, `schema_enforced`, `output_schema_sha256`); its root
  is `additionalProperties: false`, so **a pinned pre-2.0 copy of
  `model-invoke-complete.payload.schema.json` rejects new rows** — refresh the
  copy (same class as the v1.196 §3 catch-up).

## 3. Backward-compatibility guarantees

| Surface | Guarantee |
|---|---|
| `LOA_CHEVAL_LEGACY_WIRE=1` | Anthropic request body byte-identical to v1.202.1 (4096 default, no `thinking`, string `system`, no `output_config.format`) |
| Catalog ids | No Anthropic id removed; `claude-opus-4-7`, `claude-opus-4-8`, `claude-fable-5` resolve by explicit pin |
| Removed config keys | `repair_loop`, `effort:` are ignored, never rejected (no schema forbids unknown keys) |
| `aleph.enabled: true` | opted-in Aleph behaviour unchanged |
| Verdict gate | files without a trailer keep the pre-2.0 prose heuristic |
| NOTES.md | shrinking edits and `rotate` are never blocked; `read --full` on request |
| Candidate JSON | `schema_version` stays 1; the new `prerelease` field is tolerated as absent on older candidates |
| Deprecation timeline | the kill switches above are kept for the whole 2.0.x line; removal would be a 3.0 item |

## 4. Tracing and debugging

- `cheval … --dry-run` prints the resolved model, effort and output budget without a call.
- `LOA_CHEVAL_LEGACY_WIRE=1` for before/after comparisons of the request body.
- `.claude/scripts/semver-bump.sh --from-tag` shows `prerelease_transition` when a CHANGELOG heading is steering the version.
- `tools/check-prompt-budget.sh` and `tools/check-ledger-hygiene.sh` are the two new CI tripwires; run them locally before pushing.
- `notes-guard.sh check` (exit 3 = over the block line) before a long session.

## 5. Validating your migration

```bash
bash .claude/scripts/check-loa.sh                       # health; prints the Aleph opt-in line
jq -r .framework_version .loa-version.json              # 2.0.0-rc.1
.claude/adapters/cheval.py --model opus --dry-run --prompt x   # resolved id + budget, no call
bash tools/check-prompt-budget.sh                        # ok
bash .claude/scripts/notes-guard.sh check                # exit 0 (or rotate)
npx --no-install bats tests/unit/semver-bump.bats tests/unit/sync-readme-version.bats
```

## 6. Soak and feedback (release-candidate period)

- Report anything you hit as a GitHub issue labelled **`2.0.0-rc`** with the
  recipe you followed and the exact command output.
- Fixes land on `main` and are prepared as `2.0.0-rc.2`, `-rc.3`, … by the
  pipeline (the merge on an rc tag increments; nothing to do on your side).
- Promotion to `2.0.0` follows the exit criteria listed in
  `grimoires/loa/reports/release-notes-2.0.0-rc.1.md`; the rc headings stay in
  the CHANGELOG as history.

### 2.0.0-rc.2 addendum — NOTES.md rotation on upgrade, sectioned artefacts

- **`update-loa` rotates an oversized NOTES.md.** The bounded-NOTES fences from
  rc.1 refuse appends at 200 KiB; a repository that upgrades with a NOTES.md
  already past that line would have its first append blocked. `update-loa.sh`
  now runs `notes-guard.sh check` after the refresh and, on exit 3, runs
  `notes-guard.sh rotate` and logs it: the whole file is archived first under
  `grimoires/loa/archive/notes/NOTES-<UTC>.md` (fsynced, never stashed), then
  the live file keeps the recovery sections (`## Blockers`, newest
  `## Session Continuity`, three newest `## Decision Log`) plus an
  `## Archive pointers` line. Below the line nothing happens. To rotate by
  hand: `.claude/scripts/notes-guard.sh rotate --file grimoires/loa/NOTES.md`.
- **Read big artefacts by section.** `notes-guard.sh read --file <prd|sdd|sprint|NOTES>.md
  --section 'Sprint 3'` (or `--section 4.` for a numbered SDD section, or any
  heading substring) returns one H2 block under the 68 KiB cap; `--index`
  lists every H2 with line range and bytes. For any file other than NOTES.md
  the flag-less default is the index. `/loa` prints an `Artefacts:` line with
  the four sizes and flags anything ≥ 100 KiB.
- **Runs check themselves before starting.** `/run`, `/run sprint-plan`,
  `run-bridge` and `/run-resume` now run `.claude/scripts/run-preflight.sh
  --unattended` first and stop on a failed predicate with the fix named
  (permission mode, allow rules, review voices, provider breakers, NOTES size,
  a stale or halted run, beads, branch). A halted or idle run is announced at
  session start (`Run: sprint-plan HALTED (13h ago) → /run-resume`) and in
  `/loa`. Nothing to configure; run it by hand to see your own checklist.
- **Provider health and breaker reset.** `/loa` prints a `Providers` block;
  `python3 -m loa_cheval.routing.breaker_cli --list` shows every breaker with
  its age and probe timing, and `cheval --reset-breaker <provider>[:<auth_type>]`
  (journaled) clears one after you fixed the provider error. Repositories
  mounted before rc.2 have no `grimoires/loa/known-failures.md`; seed it with
  `cp .claude/templates/known-failures.md.template grimoires/loa/known-failures.md`
  (`check-loa.sh` warns until you do).
- **Your pre-2.0 cost history.** rc.1 moved the ledger to
  `.run/cost-ledger.jsonl`; the old rows at `grimoires/loa/a2a/cost-ledger.jsonl`
  were invisible to `cost-report.sh`. Read both with
  `cost-report.sh --include-legacy`, or fold the history into the current
  ledger once with `cost-report.sh --migrate-legacy` (rows tagged
  `legacy: true`, receipt under `.run/cost-ledger-migration-<UTC>.json`,
  idempotent). Every report now prints `Unpriced rows: N (S %)`; dated
  release ids, aliases and CLI-hop names are priced through the catalog
  (`pricing_resolution` on the row), and the budget enforcer will not call a
  day "under budget" while more than 5 % of **that day's** rows are unpriced
  (`cost-report.sh --json --window-day <YYYY-MM-DD>` shows the day's share
  next to the all-time share; older history never blocks today's verdict).
  Rows recorded before the ladder existed (`pricing_source: unknown`, cost 0)
  can be re-priced once, explicitly: `cost-report.sh --reprice --dry-run`
  shows how many the catalog can now resolve, `cost-report.sh --reprice`
  prices them as fresh rows with the same tokens and marks each one
  (`repriced_at`, `repriced_from`, `cost_estimated: true`), keeps every other
  line byte-for-byte, holds the writer's own lock while it rewrites the file
  in place (a `cheval` call that lands during the pass simply appends after
  it), first copies the previous bytes to `<ledger>.pre-reprice-<UTC>` (your
  recovery point) and writes `.run/cost-ledger-reprice-<UTC>.json`. Nothing
  is re-priced unless you ask.

## Non-goals / explicitly unchanged

- No change to the audit-envelope chain semantics, the zone model, or the
  hook wiring contract (the upstream hook hardening is fail-loud tightening, not a new surface).
- The per-sprint a2a record of the cycle is on the branch `record/cycle-124-a2a`, not on `main`.
