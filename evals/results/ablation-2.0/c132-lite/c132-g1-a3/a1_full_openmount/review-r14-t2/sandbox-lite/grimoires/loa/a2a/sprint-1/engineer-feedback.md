## Observations

### 1. Eval grader: bare `:N` binding credits phantom citations

- **MEDIUM** (confidence: high) `head/evals/graders/recall-vs-defects.sh:74` — the second alternative of `CITE` matches any `:N` whose preceding character is outside `[A-Za-z0-9_./:]`, so the verdict trailer's JSON (`"critical":1,"high":2,"medium":0,"low":3`, `"excluded":0`) yields five bare citations bound (`:84`) to the last cited path. Verified: a review containing exactly one citation plus a trailer reports `"citations": 6`. A manifest defect with `anchor_line` ≤ 3 in the last-cited file is then marked detected regardless of review content; the `citations` detail is inflated for every graded review; a prose token such as `port :8080` also binds.
**Suggestion:** strip the HTML verdict-trailer comment before scanning, and require the bare form to be code-fenced or preceded by whitespace and not followed by `,` inside a JSON object (or restrict it to `head:N` / `base:N`). Add an RG case with a trailer and an `anchor_line: 1` fixture (the current `review()` helper emits a trailer, but every pr-x anchor is ≥ 7, so the phantom hits never show).
**Benefit:** recall and false-positive figures stay honest; Task 4.8's own A/B rule depends on them.

### 2. Permission grammar: universal `Bash` rules are not recognised (pre-existing, now over-documented)

- **MEDIUM** (confidence: high) `head/.claude/scripts/check-permissions.sh:164` — `rule_key` returns 1 for a bare `Bash` rule and maps `Bash(*)` to the exact key `=*`; neither can cover a required `Bash(git push:*)`. An operator whose settings allow `Bash` is told all 16 required permissions are missing and `/run` preflight refuses to start; a `Bash` entry under `deny` is ignored and the checker reports every permission effective while the harness denies each command (the run then fails loudly at its first Bash call). The cross-model dissent rated this BLOCKING; I downgrade it because `pr/base/.claude/scripts/check-permissions.sh` (`base_pattern_of`) never matched a bare `Bash` either, so the PR does not introduce the gap, and neither branch loses data. The PR does overclaim parity at `head/docs/migration/v2.0-model-generation-floor.md:258` ("reads permission rules the way Claude Code does").
**Suggestion:** treat `Bash` and `Bash(*)` as a universal wildcard key for allow and deny in `rule_key`, add CP cases for both, or soften the migration-doc sentence to the two trailing-wildcard forms the grammar actually covers.

### 3. Authoritative opt-in trusts a model-authored field

- **MEDIUM** (confidence: high) `head/.claude/hooks/compliance/implement-gate.sh:115` — with `implement_gate.mode: authoritative` in `.loa.config.yaml`, the gate reads `tool_input.active_skill` (which the file header at lines 12–15 states is model-authored) and `exit 0`s on `implement|bug|run|simstim` (`:128`). A model that writes `"active_skill":"implement"` into its own Write/Edit input bypasses the fail-ask on any App Zone file; `tests/fixtures/pretooluse-payloads/expected.tsv` row `write-src-active-implement.json … allow` documents exactly that outcome. The mitigation is that the key is undocumented and IG-11 (`head/tests/unit/implement-gate.bats:151`) pins it undocumented, so the default heuristic posture is unchanged (CWE-807, reliance on untrusted input in a security decision).
**Suggestion:** either delete the authoritative branch until a harness-set signal exists, or make the opt-in refuse to take effect unless `platform-features.json` carries `harness_signal: true` (which `detect-platform-features.sh` never writes today). A one-line WARN on stderr when the opt-in is active would also keep the operator honest.

### 4. Catalog encodes two readings of one vendor pricing fact

- **LOW** (confidence: medium) `head/.claude/defaults/model-config.yaml:477` — the `claude-opus-5-5` comment cites "Claude 4.6 and later models … include the full 1M token context window at standard pricing" to omit a `long_context` tier, while the sibling 4.6-and-later entries keep a 2.0×/1.5× `long_context` tier marked `verified: false` (`claude-opus-5` at `:562`, `claude-fable-5-1` at `:408`, `claude-fable-5` at `:465`, `claude-sonnet-5` at `:772`), and `test_five_family_declares_the_beta_header_list_and_the_long_context_tier` / `test_entries_outside_the_five_family_carry_no_long_context_tier` (`head/.claude/adapters/tests/test_anthropic_catalog_floor.py:277`) lock both readings in. No runtime effect today: every probed ceiling is 180,000, under the 200,000 threshold, so the multiplier never fires.
**Suggestion:** pick one reading for the generation (or record which vendor page each entry follows) before any ceiling is calibrated above 200K.

### 5. Prompt budget raised to exactly fit

### 6. `rule_key` failure modes for shapes not in today's requirement list

- **LOW** (speculative, confidence: low) `head/.claude/scripts/check-permissions.sh:235` — `rule_key "$perm"` runs without `|| …` under `set -euo pipefail`; a future non-`Bash(...)` required rule aborts the preflight silently with exit 1 instead of a "missing" report. For an exact-form requirement the base derivation `base="*${key#\*}"` keeps the `=` sentinel (`*=git`), so a `Bash(git:*)` allow would no longer cover it. Every current requirement is `Bash(<cmd>:*)`, so nothing fails today.
**Suggestion:** `rule_key "$perm" || { missing_permissions+=("$perm"); continue; }` and derive `base` from `${key#[*=]}`.

### 7. `model-adapter.sh` stderr capture aborts on a failed `mktemp`

- **LOW** (confidence: medium) `head/.claude/scripts/model-adapter.sh:656` — `err_file="$(mktemp …)"` under `set -e`: if `$TMPDIR` is unwritable or full, the shim exits before invoking the model with no `error` line, where before this change the invocation ran with stderr discarded.
**Suggestion:** `|| err_file=/dev/null` with a one-line WARN, so a temp-dir hiccup degrades to the old behaviour.
