# Review: sprint-262 — ablation-row.sh 1.2 (defects_missed, regressions_final_green) and ablation-report.py 1.2.0

Scope read: the full head.diff plus the head copies of both harness scripts, both bats files and the fixture generator. The suite file and the ablation-runs fixtures are not in the PR, so I built a stand-in evals/suites/ablation-2.0.yaml and ran ablation-report.bats (32 of 35 pass; the 3 failures are explained below), ran ablation-report.py on all 11 generated scenarios, ran ablation-row.sh --validate on every generated runs.jsonl and on hand-crafted bad rows, and probed the new batch record with hostile inputs. The ablation-row.bats row-building tests could not be run (fixture run directories absent); the new jq expressions were checked by reading and via --validate.

## Findings

head/evals/harness/ablation-report.py:1081 — HIGH: batch_record() sorts grader_versions with a key that splits each version on "." and converts digit-only parts to int, so two grade.json files whose grader_version strings differ in shape (e.g. "1.2.13" beside "1.2.13-rc", or any non-numeric tag) raise `TypeError: '<' not supported between instances of 'str' and 'int'`. The exception is not a Fail, so the report dies with a traceback, exit 1 (not the documented 2) and neither --out nor --json is written. This contradicts the header's "a missing directory is counted, never fatal" contract for a presentation-only section. Reproduced by adding `{"grader_version":"1.2.13-rc"}` under pr-2/a0_bare/rc-02-t1. Fix: make the key total (e.g. compare tuples of (is_digit, int-or-0, str) per part) or catch and fall back to a plain string sort.
head/evals/harness/ablation-report.py:1054 — LOW: the row's `arm` is joined into a filesystem path (`<batch dir>/<arm>`) without the arm grammar check that ablation-row.sh enforces; load_rows() only requires a non-empty string. A row with arm "../../x" makes the batch record list and read grade.json files from an unrelated directory and tallies them under this batch (reproduced: the pr-2 grader tally changed to 1.2.5 ×2). Reject or skip arms not matching ^[a-z][a-z0-9_]{0,63}$ before building the path.
head/evals/harness/ablation-report.py:831 — LOW: version_key() returns None for a non-integer float suite_version (2.5) but returns "2.5" for the string "2.5". A float 2.5 row is therefore reported as "has no suite_version" when two versions are present (misleading message, reproduced) and is silently pooled into the single present version otherwise, which is exactly what the partition is meant to prevent. Treat non-integer floats like their string form (or refuse them explicitly).
head/evals/harness/ablation-report.py:1151 — LOW: render_batches() prints extra_models entries with Python's `None` ("runs None, output tokens None") when STATUS.json has an extra_models value of null or a dict without those keys; every other n/a value in the table is rendered as "n/a".
head/evals/tests/ablation-report.bats:487 — LOW: AR-33 compares jq string interpolation of floats against "1.0 … 27 27"; jq 1.6 renders the JSON literal 1.0 as "1" (the report itself writes 1.0, verified in report.json), so the test is green only on jq ≥ 1.7. The same pattern is at line 498 (AR-34 expects "1.0 3.0 0.875 10.0 -0.125"). Compare numerically (`.precision == 1`) as the older AR tests do, or pin the jq version the suite needs.
