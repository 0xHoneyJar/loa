## 1. Project Architecture

### 1.1 Principle
Three narrow changes at existing seams. Nothing new is dispatched; a route is gated, a default is resolved where every other request field is resolved, and a measurement tool gains a second transport. Every change is fail-closed: an absent key means off, an unresolved default means "send nothing" (today's behaviour), a partial probe writes nothing.

### 1.2 FR-1 — agy opt-in gate
- **D-1.1 The key.** `hounfour.headless.agy_opt_in: boolean` in `.loa.config.yaml`, default `false`, beside `hounfour.headless.mode` (`.loa.config.yaml.example:741`). Read by cheval as a node-level `yaml.compose` of the `.loa.config.yaml` under cheval's own install root (`loader._opt_in_root`; never a cwd-ancestor file) behind a trust check (owner = euid, not group/world-writable) — r251-4 amended the first-round `load_project_config` read; the bash lib and Bridgebuilder read the same file under the same rule. No environment override (a planner must not be talked into a voice by ambient env; the audit-round convention of cycle-126).
- **D-1.2 The adapter refuses.** `AgyHeadlessAdapter` checks the key before any binary discovery or spawn. Off → raise the existing configuration-error class with the message `agy headless route is opt-in: set hounfour.headless.agy_opt_in: true (the prompt travels on the CLI's argv, readable by local users; the CLI must be OAuth-authed)`; exit class `INVALID_CONFIG`, retryable false, `failure_class: opt_in_required`. On → today's path unchanged (binary discovery, the one-time argv WARN, dispatch).
- **D-1.3 Planners plan around it.** The seam is the failure class: `adversarial-review.sh` (companion planning), `flatline-orchestrator.sh` (tertiary), Bridgebuilder (`config.ts` model registration via `cheval-delegate`) and `run-preflight.sh` / `loa-status.sh` (Providers) treat an agy route whose opt-in is off as **not planned** (`planned: false, reason: opt_in_required`) rather than as a failed voice: `voices_planned` excludes it, verdict quality is computed over planned voices only, and `/loa` prints `google · agy: opt-in (disabled; hounfour.headless.agy_opt_in)`. Bridgebuilder resolves the gate before registering the google voice: when the google route is `gemini-headless`/agy (the host has no `GOOGLE_API_KEY` HTTP route or `hounfour.headless.mode` is `cli-only`), the voice is skipped with the reason logged, so `verdict_quality` is not DEGRADED on its account. Where a voice is planned by an operator-authored chain (`companion_chain`, Flatline `tertiary`) the same `planned: false` reason applies — an explicit configuration naming agy does not override the opt-in; the WARN names both keys.
- **D-1.4 Tests.** Adapter: off → refusal before discovery (no subprocess, asserted by a spy); on → discovery proceeds (binary absent here → the existing `PROVIDER_UNAVAILABLE`). Dissent: a companion chain naming `gemini-headless` with the opt-in off yields `planned: false, reason: opt_in_required` and a two-voice verdict quality that is not DEGRADED on its account; with the opt-in on and no binary, the voice fails as today. Bridgebuilder (`__tests__`): registration skips google when the route is agy and the opt-in is off; verdict quality counts planned voices. Preflight/`/loa`: the Providers line. Each red first.

### 1.3 FR-2 — Opus 5.5 catalog effort default
- **D-2.1 The field.** `params.default_effort` (enum `low|medium|high|xhigh|max`) added to `$defs/modelEntry.properties.params` in `model-config-v3.schema.json` (the block is `additionalProperties: false` by design — "a misspelt gate must not silently no-op"). `claude-opus-5-5` sets `default_effort: high` with a comment citing the vendor default `medium` (claude-api reference 2026-10-07) and Opus 5's `high`. No other entry sets it in this cycle.
- **D-2.2 One chokepoint.** In `cheval.py`, where the `CompletionRequest` is built (`effort=getattr(args, "effort", None)` at the three sites), effort becomes `args.effort or entry.params.default_effort or None` through one helper `resolve_effort(args, entry) -> (value, source)` with `source ∈ {caller, catalog, none}`. The adapters are unchanged in contract: the HTTP adapter already emits `output_config.effort` when `request.effort` is set (`anthropic_adapter.py:268-282`, with `_effort_for_model` downgrades), the headless adapter already puts `request.effort` first (`_resolve_effort`). The headless `extra.effort` rung stays as a lower-precedence legacy.
- **D-2.3 Record it.** The MODELINV envelope gains `effort_source` next to `effort` (schema addition, additive). `--dry-run` prints `effort: high (catalog default)` / `effort: low (caller)`.
- **D-2.4 Docs.** Migration addendum: the "pass `--effort high`" caveat is replaced by the default and the override; SDD cycle-126 D-4.1 amendment gets a one-line pointer; CHANGELOG; bd-9qe2 closed with the evidence.

### 1.4 FR-3 — Ceiling probe through the headless route
- **D-3.1 Transport option.** `tools/ceiling-probe-live.py --transport {api,claude-headless}` (default `api`, unchanged). `claude-headless` invokes `${CLAUDE_HEADLESS_BIN:-claude}` with exactly the adapter's shape (`-p --output-format json --permission-mode plan --no-session-persistence --tools "" --model <id>`, prompt on stdin, `--max-turns 1` if the adapter uses it — mirror `claude_headless_adapter.py:255-300`), one call per bisection step, `max_tokens`-equivalent kept small (the adapter's own output cap flag if any). OK criterion: a completed JSON result with a `result`/`stop_reason` and no `is_error`; a size failure is the CLI reporting the provider's context/token-limit message (`is_context_limit_message` / `is_token_limit_message` reused from `loa_cheval.routing.ceiling` by adding the adapters path to `sys.path` as the orchestrator does); any other failure stops with exit 1. Cost accounting uses the catalog pricing for the id (Bedrock pricing differs; the record notes `pricing_basis: catalog_estimate`).
- **D-3.2 Record and write.** The record adds `transport`, `cli_bin`, `cli_model` (the wrapper's resolved id when discoverable — `ANTHROPIC_DEFAULT_OPUS_MODEL` for `opus`), `host_route` note. `--write-catalog` with `--transport claude-headless` sets `probed_ceiling: <largest_ok>` and `ceiling_calibration: {source: operator_set, calibrated_at: <now>, sample_size: null, stale_after_days: <existing or 90>, reprobe_trigger: "API-transport probe (tools/ceiling-probe-live.py --transport api) from a host with ANTHROPIC_API_KEY; this bound was measured through claude-headless on Bedrock (<cli_model>) on <date>"}`; the `loa:shortcut` marker comment on the entry is replaced by the provenance comment. `partial: true` (budget cap) or any non-size failure → exit 3 / 1, nothing written.
- **D-3.3 Consumers.** `cheval` already derives the bound from `probed_ceiling` until `calibrated_at` is set and from `ceiling_calibration` after (cycle-124/126 policy); `ceiling_stale` follows `stale_after_days`. Bridgebuilder's generated registry (`gen-bb-registry.ts`) and `generated-model-maps.sh` regenerate from the catalog; their tests read the catalog value.
- **D-3.4 The run.** `CLAUDE_HEADLESS_BIN=$HOME/.local/bin/claude-bedrock tools/ceiling-probe-live.py --model claude-opus-5-5 --transport claude-headless --min-tokens-probe 180000 --max-tokens-probe 1000000 --budget-usd 20 --output grimoires/loa/reports/2026-10-07-opus-5-5-ceiling-probe-cli.json [--write-catalog]` run by the lead once, after the tool's tests are green; the catalog write is a reviewed diff in the sprint. Tests pinning `180000` for `claude-opus-5-5` (`cycle-124-anthropic-catalog.bats`, `model-config-v3-schema.bats`, `loa-status-providers.bats` LSP-5, `gen-bb-registry-codegen.bats`, `test_anthropic_catalog_floor.py`, `test_ceiling_e2e.py`, `test_input_size_consumers.py`, `test_providers.py`, `test_ceiling_probe_write_catalog.py`, `migrate-preserve-thresholds.bats`, `adversarial-review-companion.bats`) are audited: policy pins stay, literal pins of the Opus 5.5 value read the catalog.

### 1.5 Flatline review integration (2026-10-07)
Two-voice Flatline reviews of the PRD and this SDD ran (codex-headless + claude-headless); cross-scoring was degraded (`scoring_degraded: true`, KF class recorded in NOTES), so no HIGH_CONSENSUS set was produced and the lead integrated the raw improvements by judgment (`~/.cache/loa/cycle-127/flatline-127.log`, `a2a/flatline/{prd,sdd}-final_consensus.json`). Adopted:
- **D-1.5 One predicate.** `agy_route_planned()` in a shared bash lib under `.claude/scripts/lib/` and its Python twin in `loa_cheval/config/loader.py` are the only readers of the rule; every planner and the adapter call them.
- **D-1.6 Distinct class.** The refusal is `AgyOptInRequiredError`, a `ConfigError` (`INVALID_CONFIG`, retryable false) carrying `failure_class: opt_in_required` — distinct from `PROVIDER_UNAVAILABLE`, never a circuit-breaker increment (the planning-doc label "ROUTE_DISABLED" was shorthand for this; the wire code is `INVALID_CONFIG`). `planned: false` reasons: `opt_in_required | binary_absent | no_credentials | no_route`. Opt-in `true` with `agy` absent is a planned voice that fails (DEGRADED is then correct).
- **D-1.7 Surfacing.** A one-time WARN names `hounfour.headless.agy_opt_in` and the argv reason when `agy` is on PATH or a Gemini key is set while the opt-in is off. A fake-`agy`-on-PATH negative test proves the gate never spawns. Bridgebuilder registration carries a decision table (key presence × `agy` on PATH × opt-in × Gemini HTTP route) as comment and parametrised test. The Flatline tertiary stays commented here; the key governs it where configured.
- **D-2.5 Precedence.** caller > catalog `params.default_effort` of the *resolved* entry (aliases carry no params) > a CLI entry's legacy `extra.effort` > none; `effort_source ∈ caller|catalog|extra|none`; `effort_effective` is the wire value after `_effort_for_model` downgrades (HTTP) or pass-through (CLI), in MODELINV and the dry-run line.
- **D-2.6 Validation.** The v3 schema rejects a bad `params.default_effort` at validation time; the catalog is not schema-validated at load in production, so `resolve_effort` validates the value against the five levels and skips an invalid one with ONE WARN per (model, reason) per process — never a crash, and never shadowing an explicit caller value; an entry setting both `extra.effort` and `params.default_effort` WARNs once and the catalog value wins. `effort_effective` records the wire value after the adapter's per-family mapping. Operators override per project through the existing `hounfour.providers.*.models` overlay.
- **D-2.7 Cost/latency.** Only `claude-opus-5-5` carries the default; unattended dissent/Flatline/review hops through the headless adapter already run under the 5-family timeout (`deriveTimeoutMs`, cycle-126); a Risks row tracks KF-037 timeouts under `high`.
- **D-3.5 Measure, verify.** The CLI transport passes `--output-format json`, takes the accepted size from the response `usage` (input + cache creation + cache read), and counts an attempt OK only when the completed `result` echoes a random needle placed at the end of the prompt; a completed reply without the needle is `unverified`, not OK.
- **D-3.6 Probe call shape.** `--effort low --max-turns 1` on every attempt (the probe bypasses cheval; FR-2's default does not apply); argv built by `build_headless_argv()` extracted from `claude_headless_adapter.py` and imported — no hand mirror.
- **D-3.7 Classification and bounds.** Size failure = provider or CLI-local context/token-limit message in `result`/stderr; transient (throttling, 429, 5xx, network) → 3 attempts with backoff; per-attempt timeout scaled to input size; 1 MB output cap; JSON parse failure = `other` → exit 1. `--tolerance-tokens` (default 16,000) stops the bisection; cost = measured input tokens × catalog price when the CLI reports no reliable cost; the worst-case step cost is printed before the first call.
- **D-3.8 Write semantics.** The record is always written (`partial`/`error`/`unverified` set); the catalog is written only on a clean verified bound — or, since r251-1 (D-3.11), on a partial record when the operator passes `--write-partial-as-operator-set`, in which case the entry carries `probe_outcome: partial`: `source: operator_set` (enum unchanged) plus additive provenance inside `ceiling_calibration` — `method: probed_headless`, `transport`, `cli_version`, `cli_model`, `measured_input_tokens` — with the schema `$def` extended; the same safety margin as the API transport (or `raw largest_ok`, documented); a clean bound *below* 180K is written (tighten, never keep a disproved bound). The record carries the full argv, `AWS_REGION` / `ANTHROPIC_BEDROCK_REGION_PREFIX` / `CLAUDE_CODE_USE_BEDROCK` (values only, never secrets), bounds tested, budget cap, timestamp.
- **D-3.9 Guard.** A test fails if a literal Opus 5.5 ceiling reappears in the swept suites.

#### Review-dissent integration (sprint 251, run 1 — 2026-10-07)

- **D-1.8 The walk skips, the direct call refuses.** cheval's own chain walk consults the same predicate as the planners: a gated agy hop inside a `fallback_chain` (stock Google chains end at `gemini-headless`; `prefer-cli` puts it first) is recorded as `planned: false, reason: opt_in_required` in the envelope's skipped-hop list, never dispatched, never a breaker increment, one WARN per process, and the walk continues to the next hop. A chain that is agy alone — a direct `--model gemini-headless`, a direct Google voice under effective `cli-only`, or a stock Google chain under `cli-only` whose every hop is gated — is left whole and ends with `AgyOptInRequiredError` (`INVALID_CONFIG`, `failure_class: opt_in_required`, no breaker increment): the operator asked for agy.
- **D-1.9 What the route is.** `routes_to_agy(model, mode)` in `.claude/scripts/lib/agy-gate-lib.sh` and its Python twin: the literal `gemini-headless` hop, or a Google voice (`gemini*`, `google:*`) under effective `cli-only` (`LOA_HEADLESS_MODE` wins over the config). Under `prefer-api` with no Google key the HTTP hop fails on credentials before any agy hop (`no_credentials`, pre-existing), so key presence is not part of the rule. D-1.7's one-time WARN (agy on PATH or a Gemini key set while the opt-in is off) is implemented in the shared lib and the Python twin. `agy_opted_in()` reads the project config only — a framework defaults file cannot opt a host in; a present-but-non-boolean value is off and WARNs once naming the key and the expected type. A conformance test feeds the same configs to every reader.
- **D-1.10 Consumers.** Bridgebuilder: zero planned results never clear a merge (`mergeBlocked` with a reason); `api_key_mode: strict` WARNs about a configured voice the gate removed; `readAgyGate` surfaces a yq read failure as `readError` (fail-closed default kept, logged at warn, not reported as "opt-in off"); the gate is a required parameter of `validateApiKeys` so every caller resolves the pipeline's config path; `isAgyRouted` is registry-backed. `run-preflight.sh` P3 stays FAIL when every configured voice of a stage is gated, and its detail names `hounfour.headless.agy_opt_in`. New metadata values (`tertiary_model_status: disabled_by_opt_in`, `companion_skip_reason: opt_in_required`) are added to the schemas that constrain them.
- **D-1.11 Audit round (r251-4/r251-5).** The three readers share one trust rule: the exact `tag:yaml.org,2002:bool` tag (alias and merge-key nodes read off); the file must be owned by the current user and writable by nobody else — world-writable or writable by a group other than the owner's user-private group (gid = the owner's primary gid, group name = user name, no supplementary members) reads off with one WARN (r251-6 restored the UPG exception the Bridgebuilder pass showed Ubuntu umask-002 checkouts need; the trust check fstat's the descriptor it read); cheval anchors the read to its install root; the lib's include guard is shell-only (`declare -F`) and `run-preflight.sh` fails closed without the lib; the provider maps are never cached after a swallowed read error and both readers WARN once on the name-rule fallback. Bridgebuilder blocks the merge under a config read error (strict throws). The probe writer validates `--host-route` / the resolved `--cli-model` / `cli_version` (no control characters, ≤ 200 chars) before any spend, dry-runs the exact write, and re-parses the produced YAML before `os.replace`; an implausible observed limit (< 10 % of the window or above it) never tightens a bound; the schema requires `transport: claude-headless` and `probe_outcome` for `method: probed_headless`.
- **D-2.8 Effort across the walk (existing behaviour, pinned).** Effort is resolved once against the head entry and carried on the request to every hop (`opus` → `claude-headless` sends `--effort high`); finding 54 was refuted on that evidence. A CLI entry's default stays operator-declared (the catalog does not know which model the CLI runs). `effort_effective` is adapter-derived (`wire_effort` hook: anthropic HTTP → the per-model mapping; claude-headless → pass-through; codex/agy → none unless they send it) — the pass-through-for-every-CLI-entry misreport for codex/agy hops was finding 24. The effort levels are defined once (`loa_cheval/types.py`); `_EFFORT_LEVELS`, the argparse choices and both schema enums are pinned equal to it; an invalid legacy `extra.effort` WARNs once like an invalid catalog value.
- **D-3.10 Cross-transport trust, self-healing.** A calibration governs the bound on every route of the entry (basis `calibrated`). When `ceiling_calibration.transport` is present and is not the HTTP transport, a verified provider context-limit observation (`.run/ceiling-observed.json`, cycle-126 tighten-only store) may tighten the bound on the HTTP route (`observed − 1`, basis `observed`, `calibrated` kept true in the decision); a same-transport or transport-less calibration is never lowered by observations. `/loa` and `--json` render the case: `calibrated 936000 (claude-headless); observed N below on this route, reprobe suggested`. Rationale: the 180,000 the calibration replaced was a cycle-126 conservative shortcut, not a measured HTTP rejection; the vendor window is the same on both transports; the safeguard restores the uncalibrated entry's self-correction where the route was not measured.
- **D-3.10b Units.** The catalog bound is in provider-measured tokens; cheval's chars/3.5 estimate under-counts the Opus 4.7+ tokenizer by ≈1.4× (692,678 estimated for the 972,887-measured accept) and chars/4-class estimates (the probe filler's cl100k unit, Bridgebuilder's coefficient 0.25) by ≈1.8×. On a calibrated entry the Anthropic HTTP adapter's `count_tokens` trigger drops from 0.9 to 0.5 × bound (named constant; the count is free and authoritative; a count failure leaves the decision at `warn`); Bridgebuilder's generated input budget for a measured-unit calibration is (bound − the 20,000 headroom) ÷ `MEASURED_TO_ESTIMATE_SAFETY = 1.8`, rounded down to the thousand (508,000 for `claude-opus-5-5`), since it has no count before building the prompt. The `claude-headless` route carries no HTTP ceiling and has no count endpoint: the CLI's pre-flight is the backstop (no spend; since r251-2 `ClaudeHeadlessAdapter._raise_for_error` maps the CLI's own "Prompt is too long" / `~N tokens (limit M)` rejection to `ProviderContextLimitError` — not walked, no breaker count — where it was `ProviderUnavailableError`; pinned by test). `parse_context_limit` learns the CLI's `~N tokens (limit M)` shape. The catalog value itself stays truthful (936,000).
- **D-3.11 Structured outcome.** `ceiling_calibration.probe_outcome ∈ clean|partial` and `sample_size` = samples taken (accepted + rejected) are additive schema fields; `write_catalog_operator_set()` writes both from the record and refuses a `partial` record unless `--write-partial-as-operator-set` is passed (the operator vouches for the last verified accept). The live entry carries `probe_outcome: partial`, `sample_size: 5`. The `measured_input_tokens` description names it the raw accept; the ceilings hold the I2-clamped value.
- **D-3.12 Probe hygiene.** Charging: accepted/unverified completions at max(CLI `total_cost_usd`, measured × price); provider-side rejections at the CLI-reported cost or 0; CLI-local pre-flight rejections at 0 (`charged_usd`, `charge_basis` per sample; the budget pre-check still uses the estimate). Token-limit 429s back off past the per-minute window (honouring a retry hint) and a persisting one is a `size` step (`failure_class: token_limit`), not `other` — and a bound bracketed by any rejection other than a context limit makes the outcome `partial` (an account quota is never written as a context ceiling; D-3.11's clean write needs a context-limit bracket). Classification runs on the full diagnostic (truncated only for the record); any classifier exception is `other` with the text; write prerequisites (`context_window`, the clamp inputs) are checked before the first live call (exit 2, no spend); the CLI runs in its own process group and a timeout kills the group; the 5xx heuristic requires a status context. Tests: the fake fixture is fail-closed (`CLAUDE_HEADLESS_BIN` points at a non-existent path at module scope) and every pin that depended on the un-calibrated live catalog runs on the synthetic fixture.
- **Rollback.** FR-1: default-off is the safe state (no revert needed); FR-2: delete the `default_effort` line from the entry; FR-3: revert the catalog diff and keep the report.
- **Deferred.** A minimum-planned-voices rule (quality `insufficient_voices` below N) is a policy change for a later cycle; a distinct `ceiling_calibration.source` enum value (`probed_headless`) is covered by the additive `method` field.

## 5. API Specifications

## 6. Error Handling Strategy
Gate off → `INVALID_CONFIG` / `opt_in_required`, never a spawn. Planners map that class to `planned: false`. Effort: an invalid catalog value fails schema validation at validation time; the catalog is not schema-validated at load, so `resolve_effort` skips an invalid value with one WARN per (model, reason) — never a crash, never a silent no-op. Headless size verdicts: the CLI's own pre-flight rejection is `PROVIDER_CONTEXT_LIMIT` (not walked, no breaker count) unless a throttle marker is present — `is_throttle_message()` in `routing/ceiling.py`, one rule for the adapter and the probe — in which case it is a rate limit (retried, then walked). Probe: non-size failure → exit 1 and no write; budget cap → exit 3 and no write unless `--write-partial-as-operator-set` (the entry then carries `probe_outcome: partial`); the record is written in every case with `partial`/`error` set.
