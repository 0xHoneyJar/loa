## n58: the preemption gap, stated plainly

- **Is there a real gap? Yes.** cheval compares the bound against a local estimate. On this host tiktoken is absent, so the estimate is `len/3.5` (`base.py:936`). That gives about 12.9 tokens per filler sentence against the measured 18.0, an under-count of about 1.40×. With cl100k the under-count would be about 1.8×. The provider count replaces the estimate only when the estimate reaches 0.9 × the bound (`ceiling.py:428`), which is 842,400. A prompt whose real size is near or above the 1M window can estimate around 700K, skip the count, dispatch, and be rejected by the provider after upload. Before this sprint the 180K bound preempted such prompts, so the sprint widened a pre-existing estimator class.
- **The observed-bound store does not mitigate it.** For a calibrated entry, `input_bound` ignores observations (`ceiling.py:124`). The real backstop is cycle-126's provider-verdict path: one retry with the output budget the provider's numbers allow, then `PROVIDER_CONTEXT_LIMIT`, not walked. The failure is clean, with no truncation; the cost is one upload.
- **The CLI-overhead margin worry is REFUTED.** The live accepts are linear: about 1.800 measured tokens per filler token plus about 3.1K fixed overhead. The 64K output reserve dwarfs that. The 936,000 bound governs the HTTP entry, which carries no CLI system prompt, and the `claude-headless` entry has no ceiling fields.
- **Fix shape.** In the migration doc, say the bound is in provider-measured tokens, that cheval's estimator under-counts Claude 4.7+ English by about 1.4–1.8×, and what happens near the window. In a follow-up bead, scale the estimate for the Anthropic 4.7+ tokenizer or lower the count trigger for calibrated large-window entries.

## Must-fix list (sprint 251, test-first)

1. **Classifier: throttles are not size rejections (n39, n45, adjunct).** A Bedrock "Too many tokens, please wait" throttle currently classifies as a context-limit size rejection with no retry. A bracketing rejection whose `failure_class != context_limit` must make the outcome `partial`. This is the only path where a clean write can land a wrong (under-sized) bound in the shared catalog.
2. **Spend accounting (n38, n46).** A size rejection with no usage and a CLI-reported cost of 0 charges 0 and records `billed: false`. Timeouts and transients keep the estimate. The pre-check estimates cache writes at 1.25× (n35).
3. **Silent flags (n42, n49).** `--allow-partial`, `--tier` and `--itpm` with `--transport claude-headless` give a usage error (exit 2).
4. **Restore lost coverage (n40).** Run the schema-validation, neighbour-untouched and comment-count assertions on a pre-calibration fixture, not behind a live-catalog skip.
