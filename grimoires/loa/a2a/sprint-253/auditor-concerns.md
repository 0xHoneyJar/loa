# Auditor concerns — sprint-253 (cycle-128 Sprint 2), security pass

Scope: the Sprint 2 code (commit cea919ca plus the review round r253-1 fixes). Review findings are already in engineer-feedback.md; look for what the review did not.

1. Untrusted text paths. Map docs, ticket bodies, research reports and ledger free text are agent- or operator-authored and are re-surfaced: `chart-ticket.sh handoff` inlines the map doc, the ledger rows (`dec-write-lib.sh list --format md`) and each research report (L6 sanitizer; a fallback line when it is unavailable) into `grimoires/loa/context/chart-<slug>.md`, which `/plan-and-analyze` reads as priority-1 context. Is every surfaced string control-stripped? Is the hand-off snapshot PII-scanned anywhere (the map and spike validators scan their own files; the snapshot and the research reports are not validated)? Does `san1` cover every value that reaches `br` or the ledger (title, body, --why, --line, --name, --reason)?
2. Path handling. `--root`, `--ledger`, slugs (`SLUG_RE` lowercase), `marker()` under `grimoires/loa/research/`, `mktemp` beside the map doc, the `.chart-<slug>-<ticket>.dispatch` markers (left behind on a failed `research-end`?), `chart-frontier.sh` resolving `grimoires/loa/maps/<target>.md`, the validator's `_beads_crosscheck_available` root test (`"$dir/" == "$root/"*`), `_fr11_spike_decided` ledger path from `git rev-parse --show-toplevel` (a worktree's toplevel vs the main tree's ledger), symlinked ledger refused.
3. Privilege of the chart session. `allowed-tools`: `Bash(br *)`, `Bash(git worktree add *)`, `Bash(git push -u origin spike/*)` (push any spike branch to origin from an interactive session), `Agent` (the researcher: after r253-1 it has Read/Grep/Glob/WebFetch only; confirm no Write/Edit/Bash remains and that the session, not the agent, writes the report). `chart-unblock-probe.sh` runs an arbitrary argv in a detached worktree that shares the object database and remotes: what can a probe do that the main-tree snapshot never sees (push, tag, `git update-ref`, writes to `~`)? Is that boundary stated?
4. The fence. SP-1 regexes are bounded (`[^;&|]*` spans, no nested quantifiers); confirm no catastrophic backtracking on a long command line; the `gh pr create` on-spike-branch check runs one `git rev-parse` per matching command; the FR-1.1 spike unlock keys off a tracked YAML (operator-owned trust boundary; the consequence is a local delete of a pushed branch); the r253-1 narrowing of the merge span must not reopen a genuine `git merge spike/x` or `git -C dir merge spike/x`.
5. ICE. `safe_merge` runs `git merge --no-edit` on a spike head; `is_spike_branch` glob (`spike/*`, `*/spike/*`); detached HEAD is `HEAD` and stays blocked; `safe_pr_create` refuses a spike head; the r253-1 conflict message returns git's exit code and performs no abort itself.
6. Validators. `validate_map`: the H2 allowlist, one H1, DEC cite regex, URL ban, two-line blockquotes, PII scan; `_validate_map_beads` feeds `br` output to `jq --argjson` (size, malformed JSON path), reads the ledger with yq v4 only; `validate_spike` Pointer/Decided-by regexes, the spike-branch checkout WARN; `validate_sprint_beads` two `br list` calls (fail posture: WARN, never a silent pass?).
7. Unattended posture. `chart-guard.sh` fails closed on an unreadable context; `--close-consumed` is the only unattended operation and after r253-1 requires Status handed-off and zero open rows; `golden_resolve_open_map` exits 1 unattended with several maps; `_gp_is_unattended` falls back to `LOA_UNATTENDED` only when the writer is missing; `interview.unattended_prototype: defer|halt` (the planning skills create the bead and open row unattended, which lands `proposed` with `proposed_by: agent`).
8. Tests. Stub `br` and temp ledgers only (no live beads or ledger writes, no files outside temp dirs); the fence corpus `cwd: repo` fixtures; the new decided-unlock bats builds its own repo and ledger; root-skip where chmod is the failure injection.
