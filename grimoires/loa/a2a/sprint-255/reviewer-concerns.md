# Reviewer concerns — sprint-255 (cycle-129 Sprint 1)

Areas the dissent should press on, in priority order. The diff under review is the code-only part of the sprint (fixture copies, label files, the generated register and the docs are excluded from the diff but exist in the tree).

1. **`guard-yield.sh` as a CI gate.** It parses `.claude/settings.json` hook commands against a canonical schema, cross-checks `# @guard fence:<id>` markers against `emit_block` call sites, and exits 5 on any gap. Look for: a command shape that passes the schema but points outside `.claude/`; a marker/call-site mismatch the two-way check misses; `--check` reading host state (it must be a pure function of the repository); anything from a command string, cwd, hostname or model name reaching `guards.md`, `.run/guard-yield.*` or the hooks table; the burst-replay heuristic (≥ 10 block rows in one UTC minute) misclassifying a real burst of blocks as replays; symlink resolution of hook paths.
2. **The fence edits.** `block-destructive-bash.sh` gained marker comments, a `replay: true` audit field under `LOA_AUDIT_REPLAY=1`, and one FR-1.2b message change. The corpus is unchanged (78/100/5). Look for: any behavioural change beyond the audit row; a path where `LOA_AUDIT_REPLAY` could be set by an attacker to hide real blocks from the register (the flag is honoured from the environment).
3. **`execute-agent.sh` arm toggles.** Toggles edit the sandbox copy only, after materialisation. Look for: a toggle leaking into the live tree; `LOA_EVAL_ARM_TOGGLES` JSON reaching a shell unquoted; a toggle that silently no-ops (the design says exit 2).
4. **`run-arms.sh` and the pinned worktree.** It creates a detached worktree under `~/.cache/loa/cycle-129/arms-src-<sha>/`, verifies `SHA256SUMS`, writes `MANIFEST.json`/`STATUS.json`, retries once. Look for: a dirty or wrong-commit worktree being reused; results from two models or two source commits mixing; the env variables B scrubbed from the executor (`CLAUDE_CODE_SUBAGENT_MODEL` and the session coupling variables) — is the scrub complete and does it leak the session's credentials or sockets?
5. **`seed-corpus-from-record.sh`.** It copies verbatim trees from git history and redacts secret-shaped strings. Look for: a redaction that misses a shape `no-secrets.sh` does not know; path traversal from a record-branch path into the fixture tree; `--approve` rewriting more than the header and refreezing more than it should.
6. **`validate_sprint_kinds`.** New validator rule with date gating. Look for: a task line shape it accepts that is not a task (acceptance checkboxes), a bypass via inline code or a second `kind:` token, the WARN heuristic over-firing.
7. **`cycle-ratio.sh`.** Git range handling with user-supplied SHAs; a SHA starting with `-` (should be exit 3); MODELINV path trust.
8. **`loa-status.sh` Guards line and the bats-gated seams** (`LOA_STATUS_GUARDS_FILE`, `LOA_STATUS_GUARD_YIELD_FILE`): can the seam redirect a live `/loa` to an attacker file outside tests?
9. **Path-scoped rule files.** The frontmatter form must be the one the harness honours; `rule-paths.bats` checks globs match tracked files. Look for a glob that matches nothing the rule intends.

Out of scope for this review: the eight fixture trees (verbatim history copies, redacted), the label files (lead-approved), the generated register and hooks table (`guard-yield.sh --check` is their gate), the CHANGELOG and plan documents.
