# Auditor concerns — sprint-255 (cycle-129 Sprint 1)

Security and quality audit of the Sprint 1 code (`ffd25258..HEAD`, code-only diff; fixture copies, label files, generated register and plan documents excluded). Look for what the review did not: the review approved after one fix round (`engineer-feedback-r1.md`, `engineer-feedback.md`). Press on trust boundaries and on anything that runs in CI or writes files.

1. **`guard-yield.sh` runs in CI as a gate and writes files.** It parses `.claude/settings.json`, reads `# @guard` markers from two scripts, reads the untracked audit log, and writes `grimoires/loa/guards.md`, `.run/guard-yield.{md,json}` and a block of `hooks-reference.md`. Audit: every string that reaches an output (ids, origin text, notes, registrations) and the cell sanitiser; the `install_file` temp-then-rename; the `--check` mode's purity (no host state read); the symlink and containment logic added in r255-1; whether a crafted `settings.json` command or a crafted origin map can make the script write outside its targets or exit 0 wrongly; `--root` handling.
2. **The replay flag is an environment variable.** `LOA_AUDIT_REPLAY=1` makes the fence (and later the gate) write `replay: true`, which the register excludes from the yield. Audit: can an agent session hide real blocks from the yield this way, and does the yield make that visible (it counts flagged rows)? Is the flag ever exported outside tests?
3. **`execute-agent.sh` arm toggles and the env scrub.** Toggles edit a sandbox copy; the executor's environment is scrubbed of the parent session's coupling variables and the subagent model is pinned. Audit: completeness of the scrub (sockets, session ids, credentials, `CLAUDE_CODE_*`), whether a toggle can be made to edit a path outside the sandbox (`WORKSPACE` derivation), `LOA_EVAL_ARM_TOGGLES` JSON handling, and the `yq -i` on the sandbox config.
4. **`run-arms.sh`.** Creates a detached worktree in `~/.cache`, holds a lock directory, runs background jobs, kills them on exit, verifies `SHA256SUMS` with embedded Python (`-I`). Audit: the lock and cleanup under concurrent runs; the worktree reuse checks; the transport-failure classifier (`grep -i network` on stderr); whether `MANIFEST.json` records anything secret (env, paths); the retry wait; result rows carrying `model_id` from the executor.
5. **`seed-corpus-from-record.sh`.** Copies verbatim trees from git history into fixtures, redacts secret-shaped strings, writes `labels.tsv`, `--approve` rewrites a header and refreezes `SHA256SUMS`. Audit: redaction coverage versus `no-secrets.sh`; path traversal from record-branch paths into the fixture tree (`startswith("/")`, `..`); `--approve --by` input grammar; what `--check` trusts.
6. **New validator code.** `validate_sprint_kinds` (awk over untrusted plan text); `tools/cycle-ratio.sh` (user-supplied SHAs, a `-`-prefixed SHA, MODELINV path trust, `git` run in the current repository).
7. **`loa-status.sh` Guards block.** Reads two files and prints; the bats-gated seams must not be reachable outside bats. Audit the gating condition and what `jq -er` prints from an attacker-written `.run/guard-yield.json` (control characters, pipes).
8. **The path-scoped rule files and the FR-1.2b message change.** No behaviour change intended beyond load scope and one string; confirm no fence rule weakened (corpus unchanged, D-rows intact; `floor-snapshot.bats` FS-2 and FS-4).
9. **The fixture trees under `evals/fixtures/review-prs/pr-11 … pr-18`.** They are verbatim copies of past repository states, now tracked (with their `dist/` directories re-included in `.gitignore`). Audit: any secret or token that survived redaction (run `evals/graders/no-secrets.sh` over them), any executable the harness might run from a fixture, and whether a fixture file could be picked up by a repository-wide tool (lints, tests globbing `tests/**`, the prompt-budget scanner).

Out of scope: the planning documents, the CHANGELOG, the generated register content (its generator is in scope), the decision ledger rows.
