## Summary

A dissent now plans two voices from different provider families and drops nothing silently. `adversarial-review.sh` starts a **companion chain** (the other family: an OpenAI-family primary gets `opus` → `claude-headless`, an Anthropic-family primary gets `gpt-5.5` → `codex-headless` since review round 1 — `gpt-5.5-pro` only via `companion_chain.openai`, KF-002) in a background subshell before the primary walk; credential *presence* (env → `.env.local` → `.env`, the value never read) decides only where that chain starts, and the companion's outcome is its actual completion — `metadata.companion_voice` carries the family, chain, final model, `status`, a `failure_class` (`auth | model_unavailable | quota | timeout | malformed`) and cost; both completed envelopes aggregate to `voices_planned: 2`, a failed companion is a dropped voice that never blocks a review. A finding missing only `failure_mode` (the KF-004 class — the three real rejected payloads are now fixtures) is normalised instead of dropped (`failure_mode_derived`, positional `id_derived`), every payload that still fails is summarised in `metadata.rejected_summary[]`, and `verdict-derive.sh` refuses a feedback file that does not triage a non-empty summary under `## Rejected dissent payloads`; the reviewer and auditor contracts say so within their byte budgets. The repair round-trip goes to `tiny` when an Anthropic credential is present, else `claude-headless`.

Assumptions (Karpathy rule 1), recorded in NOTES.md: the companion family is decided from the **configured** primary model (so both chains can start in parallel), recorded as `family_basis: configured_primary`; `voices_planned` keeps the aggregator's semantics (one envelope per cheval invocation — cheval walks its own inner chain inside one invocation, so a keyless host yields one envelope per outer chain, `voices_planned 2`); the companion's rejected payloads land in a `-companion` sidecar so the primary's file is never touched; a missing `id` is derived positionally (the real payloads carry `title`, not `id`) and the KF-004 corpus fixture that asserted the opposite moved with it; the opt-out key is read raw because `false // true` is `true` in yq.
