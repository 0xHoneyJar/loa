## Second-order flows

- Cache poisoning via a shared repo directory: requires write access to `.run/perf-cache` → requires `.run` owned by the victim uid AND writable by the attacker, which `_gi_trusted_dir` refuses (and now tightens when it is our own dir with a stray group bit). A row that passes the awk alphabet check renders as a table cell in INDEX.md (pipes escaped by `render_md`'s `esc`; `<>` excluded by the reader) — the worst case is a misleading decisions row in a generated index, never code execution.
- Stale consent (agy): closed by the r1 fix for same-host clocks; the remaining skew case needs a remote filesystem with a server clock behind the host and a same-size rewrite within the skew — recorded in DEC-1132.
- Chain verification regressions: `verify-chains` can only be MORE conservative than per-call (`loa-status` counts none of the passed paths on an abnormal exit); a false "7/7" needs a forged ok:true record with the right index AND path from the verifier process itself.
