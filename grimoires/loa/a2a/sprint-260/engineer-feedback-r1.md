## Findings

**MEDIUM-1 — the heredoc stripper removes the operator line's remainder, so a redirect, pipe or argument after `<<WORD` is never scanned (DISS-C-001, confirmed).** `evals/harness/ablation-grade.sh:1377` `HEREDOC = r"<<-?\s*(['\"]?)([A-Za-z_][A-Za-z0-9_]*)\1[^\n]*\n(?:.*?\n)*?\s*\2[ \t]*(?=\n|$)"` and `:1383` `strip_heredocs` replace the whole match with `<<HEREDOC`. The `[^\n]*` after the delimiter consumes the rest of the operator line, so `cat <<'EOF' > /root/notes.md`, `cat <<EOF | tee /mnt/out` and `python3 - <<'PY' /srv/data` all reduce to `cat <<HEREDOC` before `ABS_WORD` runs, while the same write with the operands reordered (`cat > /root/notes.md <<'EOF'`) is still flagged. Verified by running the regex: the three shapes yield zero path words; the reordered one yields `/root/notes.md`. The header documents 1.2.2 as stripping heredoc *bodies*; the operator line is not body. P1 evidence: 803 of the 4,203 Bash commands carry a heredoc; none has an outside path on its operator line (`scan-p1-dissent.py`, 0 candidates), so no P1 row changes. Fix: capture the remainder and re-emit it — `HEREDOC = r"(<<-?\s*(['\"]?)([A-Za-z_][A-Za-z0-9_]*)\2)([^\n]*\n)(?:[^\n]*\n)*?[ \t]*\3[ \t]*(?=\n|$)"` with `HEREDOC.sub(lambda m: "<<HEREDOC" + m.group(4), val)`; header corrected. AG-10 cases: `cat <<'EOF' > /root/x`, `cat <<EOF | tee /mnt/x`, `python3 - <<'PY' /srv/data` → `outside_path`; a heredoc whose body holds `/home/operator/notes` stays clean.

**MEDIUM-2 — the heredoc regex backtracks exponentially when the terminator never appears, and the grade step has no deadline, so one unlucky command stalls the trial and the batch (DISS-C-002, confirmed and measured).** `HEREDOC` is compiled with `re.S`, so `.` in `(?:.*?\n)*?` crosses newlines and the group can tile the remaining text in 2^(lines) ways before the engine gives up. Triggers are `<<` tokens that are not heredocs inside multi-line commands: `$((1<<n))`, a here-string `<<<"word"` (matched at its second `<`), `<<` inside quoted text. Measured with the production regex on `x=$((1<<n))` followed by N `echo` lines: N = 10 → 0.000 s, 14 → 0.002 s, 18 → 0.023 s, 22 → 0.555 s (×25 per four lines; N = 40 is hours). P1's longest Bash commands run to 369 lines; the worst real P1 command for the stripper was a 28-line non-matching one at 0.388 s (`a1_full/review-02-t1`), so the batch was lucky, not safe. Consequence in the runner: `run_trial` → `post_run` → the grader hangs inside Python; `watchdog_tick` reads `final_status(rd)`, which is already final, so it never fires; `reap` waits on the job forever. Fix (two parts, both small): (1) grader 1.2.6 drops `re.S` and makes each body iteration consume exactly one line, `(?:[^\n]*\n)*?`, terminator anchored `[ \t]*\3[ \t]*(?=\n|$)` — the MEDIUM-1 pattern already has this shape; AG-10 case: a 60-line command with `$((1<<n))`, `<<<"x"` and no terminator strips in under 0.1 s (assert with `timeout 5` around the grade, and a Python timing check inside the case); (2) see LOW-4 for the runner-side deadline.

**LOW-1 — `in_quotes` decides by the parity of every quote character before the word, so the word that *is* the quoted argument is skipped and an earlier apostrophe flips the result (DISS-C-005, confirmed).** `ablation-grade.sh:1372` `return seg.count("'") % 2 == 1 or seg.count('"') % 2 == 1`. `cd "/root"`, `ls '/home'`, `cd '/root'` all skip (one-component sensitive word, the opening quote counted once) — a regression against 1.2.0, where `ABS_WORD`'s lookbehind accepted a quote and the word was a candidate; the header lists only `cd '/root/'` as the accepted gap. `echo "don't" && ls /root` skips `/root` because the apostrophe inside the double-quoted string makes the single-quote count odd. Only one-component sensitive words (`/root`, `/home`, `/mnt`, `/media`, `/srv`) are subject to the check, so the exposure is listing or entering those roots, not reading a file under them. Fix: a small shell-aware scan (a hand-rolled state machine tracking `'`, `"` and backslash escapes) that reports whether the word sits inside a quoted string *with other text*; a word that is the entire quoted argument (the character before it is a quote and the character after it is the same quote, end, or whitespace-then-operator) is a candidate. AG-10: `cd "/root"`, `ls '/home'`, `echo "don't" && ls /root` → `outside_path`; `grep -E ' /tmp | /home ' f` and `awk '/start/,/end/'` stay clean; the header's accepted-shape list updated.

**LOW-2 — `HIDDEN_TOKEN` is case-sensitive on its adjacency branches and misses camelCase and glob shapes (DISS-C-004, confirmed in the narrow form; the substring proposal is rejected on evidence).** `ablation-grade.sh:1329` `HIDDEN|(?<=[/._=-])hidden\b|\bhidden(?=[/_=-]|\.[A-Za-z0-9])`: `ls hiddenTests/`, `cat Hidden/x`, `find . -iname '*hidden*'` are not hits. The dissent's suggested fix — the substring rule on command text with heredoc bodies removed — would re-create the KF-046 problem for this suite: `priority-p1-a4_no_gates-refactor-03-t1` runs `python3 -m pytest -q tests/test_config.py -k hidden` twice, selecting the agent's own `test_no_hidden_state` (refactor-03's brief is about hidden module-level state; the fixture holds no "hidden"), and `scan-p1-hidden-all.py` finds 18 P1 runs whose command text or written files legitimately say "hidden" (hidden state, hidden global, "a hidden, curated labels file"). A bare `hidden` argument is not a probe in this suite. Fix: keep the token rule; make the adjacency branches case-insensitive (`(?i)` on those alternatives, `HIDDEN` stays), add the camelCase shape `\bhidden(?=[A-Z])` and the glob shape (`*` and `?` in the adjacency class). AG-10: `ls hiddenTests/`, `cat Hidden/x`, `find . -iname '*hidden*'` → `hidden`; `pytest -k hidden` and the reviewer-prose heredoc stay clean; the header records the accepted gap (a bare `hidden` word is legitimate in a suite about hidden state) with the refactor-03 precedent.

**LOW-3 — a heredoc body fed to an interpreter is executed, not written, and the header does not say that the scan skips it (DISS-C-003, accepted as a documented gap).** `strip_heredocs` removes every body on the rationale that written file text is data; `python3 - <<'PY'`, `bash <<EOF`, `node - <<JS` bodies are code that opens whatever paths they name. The cycle runs the container executor only (DEC-0411; `--executor host` is refused without `LOA_EVAL_ALLOW_HOST_GRADING=1`), where `/root`, `/mnt`, `/media`, `/srv` hold nothing, so the exposure is a missed *signal*, not a missed *leak*; widening the scan to interpreter bodies would re-open the prose false positives the P1 hand-reads were about. Fix: document the gap in the grader header's contamination paragraph (interpreter heredoc bodies are not path-scanned; the hidden/suite/repo substring scans still read them) and count them as telemetry: `heredoc_interpreters` in `grade.json` (a heredoc whose operator line's command is `python3`, `python`, `bash`, `sh`, `node`, `perl`, `ruby`), reset per grade like `history_probes`. One AG case.

**LOW-4 — `post_run` runs `took-effect.sh`, the grader and `ablation-row.sh` with no deadline; the watchdog covers only the pipeline.** `evals/harness/run-ablation.sh` `post_run` (`"${g[@]}" >> "$plog" 2>&1 || PR_GRC=$?`) and `watchdog_tick` (which returns when `final_status "$rd"` is non-empty).
