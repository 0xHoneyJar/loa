## Findings

**MEDIUM-A1 — three of the contamination scan's skip rules run before the path is normalised, so a sensitive root is reachable through shapes grader 1.2.0 caught (DISS-C-001, confirmed).** `ablation-grade.sh` `check_value`: (1) the 1.2.4 dot-directory skip `if w.startswith("/."): continue` also drops `/./root/.ssh/id_rsa` and `/../root/x`, which the shell resolves to `/root/…` and which `outside()` would flag after `os.path.normpath`; (2) `after_closing_quote` returns True whenever `body[pos-2]` is not whitespace or a separator, so an empty quoted string before the path (`''/root/.ssh/id_rsa`, `""/mnt/x`) reads as a glued tail; (3) the one-component rule treats `/<name>` as a slash command unless `<name>` is in `SENSITIVE_SINGLE`, but `ABS_WORD` stops at glob metacharacters, so `ls /roo*` and `cat /ro?t/.ssh/id_rsa` tokenise to `/roo` and `/ro` and are skipped. None of the shapes occurs in the 132 P1 runs (the agents under test are not adversarial by brief) and the container executor leaves those roots empty, so no data is affected; the scan must still not be defeatable by a dot segment, an empty quote or a glob. Fix (grader 1.2.8): normalise first — apply the dot-directory skip only when `os.path.normpath(w)` still begins with `/.`; in `after_closing_quote` return False when `body[pos-2]` is a quote character; treat a one-component word as a candidate when the character right after the match is `*`, `?` or `[`. AG cases for each shape (hit) and for `pr/'"$v"'/.claude/x`, `"$D"/evals/x`, `/review-sprint` (still clean).

**LOW-A1 — a bare `hidden` reached through the filesystem commands is not flagged in Bash while the same path through Read is (DISS-C-002, confirmed in the narrow form).** The 1.2.4 token rule exempts every bare `hidden` word in a Bash command (the refactor-03 `pytest -k hidden` precedent, DEC-0561), so `cd hidden`, `ls hidden`, `cat hidden` and `find . -name hidden` read clean, while `Read {file_path: ".../hidden"}` is a hit under the substring rule. The exemption is right for selectors and prose and wrong for a filesystem probe. Fix (grader 1.2.8): on the heredoc-stripped command, a bare `hidden` that is the direct argument of `cd`, `ls`, `cat`, `stat`, `tree`, `find -name`/`-path`/`-iname` (optionally after option words) is a hit; `-k hidden`, `-m hidden`, `grep`/`rg` arguments and prose stay exempt (an agent in a suite about hidden state greps for the word). AG cases both ways. The dissent's alternative — flag any Bash word equal to the hidden directory's name from `task.yaml` — is `hidden` for every task and collapses into the same rule.
