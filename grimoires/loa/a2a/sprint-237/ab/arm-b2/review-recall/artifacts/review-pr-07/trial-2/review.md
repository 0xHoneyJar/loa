# Code Review: chore(hooks,constructs): allow bounded hidden dirs, first-match local sources, strict traversal rejection

## Scope

Three files touched, no sprint plan / beads / a2a artifacts present for this evaluation — reviewed directly against `head.diff` and the full `head/` sources per `REVIEW-INSTRUCTIONS.md`.

- `.claude/hooks/safety/block-destructive-bash.sh` — widens the `rm -rf` allow-list to admit bounded hidden subdirectories via a named exclusion set.
- `.claude/scripts/constructs-lib.sh` — `find_local_source()` drops slug validation and returns the first path with a manifest.
- `.claude/scripts/lib/symlink-manifest.sh` — replaces the normalized-resolution traversal check with a blanket "any `..` segment in link or target is rejected" rule.

## Changes Required

- **HIGH** (confidence: high) `head/.claude/hooks/safety/block-destructive-bash.sh:856-857` — The new named-exclusion set (`.git`, `.ssh`, `.aws`, `.kube`, `.gnupg`, `.docker`, `.config`, `.claude`, `.env`) is matched with case-sensitive bracket/literal alternation, but the new hidden-dir allow branch (`\./\.[A-Za-z0-9_-][^*]*`) accepts any case variant of a hidden name. On the case-insensitive-but-case-preserving filesystems this framework is routinely used on (macOS APFS default, Windows), `./.Claude/`, `./.GIT/`, `./.SSH/`, `./.ENV` etc. resolve to the *same on-disk directory* as their lowercase, protected counterparts, yet fail every alternative in `_re_allow_exclude` (case mismatch) and fall straight into `_re_allow_list`'s new hidden-dir alternative, which is ALLOWED. Concretely: `rm -rf ./.Claude/` on a fresh macOS checkout deletes the System Zone (`.claude/`) the hook is explicitly documented (lines 848–853) to protect, with no block and no ambiguous warning — a straightforward bypass of the very fence this PR is adding. Before this PR every hidden path was unconditionally blocked (bare `\.` in the old exclude list), so this bypass did not exist; it's introduced by the new allow branch. Fix: case-fold both sides of the comparison (e.g. lowercase the token before testing) or add case-insensitive alternatives to the exclusion regex.

- **HIGH** (confidence: high) `head/.claude/scripts/constructs-lib.sh:565-594` — `find_local_source()`'s docstring and signature (`Args: $1 = pack slug`) promise a source path *for that slug*, and the removed `_local_source_matches_slug()` was the only code enforcing that promise. The new loop (lines 589-593) returns the first `search_paths` entry that merely contains a `construct.yaml`/`manifest.json`, with no check that it belongs to the requested slug. This is harmless for the default search paths (they embed `$slug` in the path itself, e.g. `$HOME/src/construct-$slug`), but the `constructs.local_source_paths` config branch (lines 573-578) reads a flat, non-slug-parameterized list of directories from `.loa.config.yaml`. Concrete failure: a user configures `constructs.local_source_paths: ["~/code/pack-alpha", "~/code/pack-beta"]` (two independently cloned construct packs). Calling `find_local_source beta` walks the list in order, finds `pack-alpha`'s `construct.yaml` first, and silently returns `pack-alpha`'s path as if it were `beta`'s local source — the caller then installs/links the wrong pack's code under the trusted `beta` name. This is exactly the kind of silent construct-substitution the removed helper existed to prevent; nothing in the diff replaces that guarantee.

## Observations

- **MEDIUM** `head/.claude/hooks/safety/block-destructive-bash.sh:856-857` — Even setting aside case-sensitivity, the named exclusion set only matches *exact* segment names (`\.git($|/)`, etc.), so credential-bearing dotfiles that merely share a prefix are not covered and now fall through to the new permissive hidden-dir allow branch: `./.git-credentials`, `./.netrc`, `./.npmrc`, `./.pypirc` were all unconditionally blocked before this PR (the old bare `\.` exclude caught every hidden path) and are now silently ALLOWED for `rm -rf`. Not catastrophic (single-file, not a mass/root deletion), but it's a narrowing of protection for exactly the class of file (stored credentials) the named exclusion list was introduced to protect, and the PR's own inline comment doesn't mention this class of gap.
- **LOW** `head/.claude/scripts/lib/symlink-manifest.sh:255-259` — Replacing the normalize-and-check-resolved-path logic with an unconditional "reject any `..` in target" is stricter than before, which is safe, but it also rejects previously-valid, non-escaping constructs (e.g. a link three directories deep whose target legitimately uses `../shared/lib` to reach a sibling still inside the repo root). This is consistent with the PR title ("strict traversal rejection") and is a reasonable simplification trade-off, not a defect — flagging only in case any existing construct manifest relies on the old permissive resolution and would now fail closed (which is the safe direction to fail).

## Overall Assessment

The stated intent (loosen the over-broad hidden-path block, drop the redundant slug-match helper, tighten traversal checking) is reasonable, and the symlink-manifest.sh simplification is a net safety improvement. However, the hidden-dir allow-list change in `block-destructive-bash.sh` reopens exactly the kind of System Zone / credential-directory bypass the surrounding comments say it's closing, via a case-sensitivity gap that's very plausible in this framework's actual (macOS-heavy) usage — that must be fixed before this lands. The `find_local_source()` change also needs its slug check restored (or the config-driven `local_source_paths` behavior needs to be explicitly redefined as "first manifest found, slug is advisory only" and documented as such) before it can be considered correct.
