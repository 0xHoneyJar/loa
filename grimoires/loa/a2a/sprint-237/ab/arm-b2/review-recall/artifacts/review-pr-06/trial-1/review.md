# Code Review: pr-06 — remove spawn-failure handlers, skeptic normalization, and membrane overlays

## Overall Assessment

The PR frames itself as a cleanup/revert, but each of the three files removes a piece of
defensive code that was purpose-built to close a previously-observed failure mode, and none of
the removals is compensated for elsewhere. Two of the three are outright regressions that will
surface as either an unhandled exception escaping the provider's typed-error contract, or a
shape mismatch fed straight into the scoring engine. The third silently drops support for
manifest event-key aliases and construct.yaml event/compose_with overrides with no error or log
line, so packs that rely on those aliases/overrides will quietly lose data in the generated
index. None of this is caught by tests in the diff (no test changes are included at all).

## Changes Required

- **HIGH** (confidence: high) `head/.claude/adapters/loa_cheval/providers/claude_headless_adapter.py:159` — `run_subprocess_pgkill` is invoked inside a `try` (lines 152–182) whose `except` chain now only handles `subprocess.TimeoutExpired`, `SubprocessOutputCapExceeded`, and `FileNotFoundError` (lines 166–182). The diff deletes the `except OSError` and `except ValueError` clauses that used to wrap spawn failures (ARG_MAX/ENOMEM/exec errors, or an embedded NUL byte in the prompt argv — per the deleted comments themselves) into `ProviderUnavailableError`. Every other failure path in this method is deliberately normalized into `ProviderUnavailableError`/`ConfigError` so the multi-model fallback chain (see the `_SemaphoreExhausted`/`CHAIN-EXHAUSTED-CONCURRENCY` handling immediately below at lines 183–192) can catch it and advance to the next provider. With the two clauses gone, a raw `OSError` or `ValueError` from the subprocess call now propagates straight out of this method, uncaught, breaking the documented fallback contract and crashing the caller instead of cleanly failing over to the next model in the chain. Concrete trigger: a prompt large enough to exceed `ARG_MAX`, or a prompt containing an embedded NUL byte, raises `OSError`/`ValueError` from `subprocess`/`os.exec*` internals and is no longer converted.

- **HIGH** (confidence: high) `head/.claude/scripts/flatline-orchestrator.sh:1597` (and :1598, :1626) — `normalize_skeptic_envelope` was deleted (previously defined at `base/.claude/scripts/flatline-orchestrator.sh:297`, coercing a bare JSON array into `{"concerns": [...]}` and any non-object/non-array into `{"concerns": []}`). `extract_json_content` (called here) only normalizes markdown fences/BOM/prose wrapping — it does not enforce the envelope's shape. If a skeptic-role model response is a raw JSON array (the exact case the deleted function's `elif type == "array"` branch existed to handle), the prepared file at `$gpt_skeptic_prepared`/`$opus_skeptic_prepared`/`$tertiary_skeptic_prepared` is now passed as-is via `--skeptic-gpt`/`--skeptic-opus`/`--skeptic-tertiary` (lines 1636–1639) to `$SCORING_ENGINE`, which expects the `{"concerns":[...]}` shape used as the default everywhere else in this function (e.g. the `'{"concerns":[]}'` defaults at lines 1597, 1598, 1626). This reintroduces exactly the bug the removed function fixed — a shape mismatch reaching the scoring engine whenever a skeptic model emits an array-shaped response.

- **HIGH** (confidence: medium) `head/.claude/scripts/construct-index-gen.sh:302-303` — event extraction was narrowed from `(.name // .event // .type) // empty` to `.name // empty` for emits, and from `(.event // .name // .type) // empty` to `.event // empty` for consumes. Any pack manifest whose `events.emits[]`/`events.consumes[]` entries key their event identifier under `.event`/`.type` (emits) or `.name`/`.type` (consumes) instead of the now sole-supported key now silently resolves to `empty` for that entry, producing a truncated `emits`/`consumes` array in the generated construct index with no warning — the `2>/dev/null || echo "[]"` fallback only triggers on a `jq` error, not on a per-entry alias miss. This is silent data loss in the generated index rather than a crash, so it can go unnoticed until a downstream consumer that keys off `events.emits`/`events.consumes` (e.g. composition or routing logic) fails to see events it should have seen.

## Observations

- **MEDIUM** (confidence: medium) `head/.claude/scripts/construct-index-gen.sh:308-336,396` — the construct.yaml overlay no longer reads `.compose_with` or `.events.emits`/`.events.consumes` (previously extracted into `compose_with_json`/`cy_emits`/`cy_consumes` and merged in, per the deleted lines in the diff), and `composes_with` is now hardcoded to `[]` before `compute_composition` runs its own write/read-overlap inference. If any existing `construct.yaml` declares an explicit `compose_with` list or overrides its manifest's event names, that declaration is now silently ignored rather than erroring — the PR description frames this as an intentional revert to "manifest-only form," so this may be a deliberate scope decision, but it is worth confirming no shipped pack relies on either overlay field before merging, since there's no deprecation warning for authors who still have those keys in their `construct.yaml`.
