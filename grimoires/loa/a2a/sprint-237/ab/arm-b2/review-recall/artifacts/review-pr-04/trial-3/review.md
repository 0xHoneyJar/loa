# Review: chore(cheval,flatline,status): shorten headless env scrub, temp-file handling, flag parsing

## Changes Required

- **HIGH** (confidence: high) `head/.claude/adapters/loa_cheval/providers/base.py:472-476` — `_HEADLESS_STRIPPED_AUTH_VARS` drops `GOOGLE_GENAI_USE_VERTEXAI`, `GOOGLE_GENAI_USE_GCA`, `GOOGLE_GEMINI_BASE_URL`, and `GEMINI_CLI_USE_COMPUTE_ADC` from the strip list, while the surrounding comment block (unchanged by this diff, `head/.claude/adapters/loa_cheval/providers/base.py:463`, `head/.claude/adapters/loa_cheval/providers/base.py:493`) still says the helper "closes issues #879 / #880". Those four vars are exactly the Gemini CLI auth-mode selectors the original fix targeted: if a headless caller's parent process exports `GOOGLE_GENAI_USE_VERTEXAI=true` (or `_USE_GCA`, a custom `GOOGLE_GEMINI_BASE_URL`, or `GEMINI_CLI_USE_COMPUTE_ADC=1`) — plausible in any CI/dev box that also does interactive Gemini/Vertex work — `build_headless_subprocess_env()` now passes them straight through to the subprocess. The gemini CLI will then route through Vertex AI / a custom endpoint / ambient ADC compute credentials instead of the intended OAuth-subscription auth path, silently defeating headless isolation and potentially sending prompt/request data to an operator-controlled endpoint the caller didn't intend to use. This is a direct reopening of #879/#880, not a harmless doc trim — the PR description ("shorten... env scrub") does not disclose that stripped variables were actually removed from protection, only that wording was shortened.

## Observations

- **MEDIUM** (confidence: medium) `head/.claude/scripts/flatline-orchestrator.sh:577-579` — the `mktemp` failure guard (`if ! tmp=$(mktemp ...); then log WARNING; continue; fi`) was removed. The call site (`aggregate_and_write_final_consensus ... || true`, not shown in this diff but present a few hundred lines later in the same file) wraps the whole function in `|| true`, which disables `errexit` for everything inside it — so a `mktemp` failure here no longer aborts the script, but `tmp` becomes an empty string, `printf '%s' "$vq" > "$tmp"` fails on the empty redirect target, and (with errexit suppressed) the loop still appends the empty `"$tmp"` to `vq_files`/`cleanup_files` before continuing. That silently feeds a bogus empty path into the Python aggregator instead of skipping the file as the function's own docstring promises ("Fail-soft: ... logs a warning but does NOT abort"). Low-likelihood (requires `/tmp` exhaustion or a permissions problem) but a real deviation from the documented contract; worth restoring the `continue` (the `log ... skipping` message is more useful than a downstream aggregator failure) even though the `local tmp` declaration remains.
- **LOW** (confidence: medium) `head/.claude/scripts/flatline-orchestrator.sh:2282` — the analogous guard around `arbiter_prompt_file=$(mktemp)` also went away, but here it's effectively a wash: the removed guard's failure path called a bare `continue` with no enclosing loop (the nearest `for` loops are at lines 2304/2308, both *after* this call), so under the file's `set -euo pipefail` (line 47) that `continue` would itself have aborted the script on failure (invalid `continue` outside a loop). Net behavior on `mktemp` failure is unchanged — script termination either way — so this hunk is dead-code cleanup rather than a regression, but flagging for the record in case a future refactor reintroduces a real loop here without restoring a real guard.
- **LOW** (confidence: high) `head/.claude/scripts/loa-status.sh:29-35` — colors are now assigned unconditionally, removing the prior `[[ -z "${NO_COLOR:-}" ]] && [[ -t 1 ]]` gate. This breaks the `NO_COLOR` convention (an explicit `NO_COLOR=1` from an operator is now ignored) and means every non-TTY consumer — output piped to a file, captured via `$(...)`, redirected into CI logs, or grepped by another script for strings like `Warning:` or a version number — gets raw ANSI escape sequences interposed in the text. The JSON-output branches (`JSON_OUTPUT` gated blocks around lines 475/484) appear to avoid the colored echo lines, so this doesn't corrupt `--json` output, but it does regress the plain human-readable path whenever it's not attached to a real terminal.
- **LOW** (confidence: high) `head/.claude/scripts/loa-status.sh:62-64` — the unknown-argument rejection (`UNKNOWN_ARGS` tracking + `dx_unknown_flag`/usage-and-`exit 2` fallback) was deleted. Outside `--economy` mode, an unrecognized flag (e.g. a typo like `--jso`) is now silently swallowed into the unused `ECONOMY_ARGS` array instead of producing an error, so a mistyped invocation exits 0 and prints normal status instead of surfacing the mistake to the caller (human or script).

## Overall Assessment

The `base.py` change is not a safe simplification: it quietly narrows the set of environment variables `build_headless_subprocess_env()` strips, re-exposing the exact Gemini CLI auth-mode-selector leak that issues #879/#880 were opened to close, while the docstring/comment still claims those issues stay closed. That alone requires changes before this can be approved. The `flatline-orchestrator.sh` and `loa-status.sh` hunks are lower-stakes cleanups; one (`vq-input` mktemp guard) has a real, if narrow, fail-soft-contract violation worth fixing in the same pass, and the `loa-status.sh` color/unknown-arg removals are UX/tooling regressions rather than correctness bugs.
