- **CRITICAL** (confidence: high) `head/.claude/hooks/safety/block-destructive-bash.sh:207-236` — Dropping the quote-exclusion from the carrier prefix classes (`[^;&|'"]*` → `[^;&|]*` at lines 210-212) removes the guarantee that these greedy prefixes stop before the first quoted value. Bash's `=~` (glibc ERE) matching is leftmost-**longest**, so when a segment contains two same-type flags — e.g. `git commit -m "<value1>" -m "<value2>"` — the regex now prefers the longest overall match, which spans from `git` through the **second** `-m`'s value, using that second value as the sole captured group (`vi=$(( ${#BASH_REMATCH[@]} - 1 ))` in `_bdb_scrub`, line 223). Since the multi-flag tail loop (`_bdb_re_tail`, present in `base/.claude/hooks/safety/block-destructive-bash.sh:214,236-248`) was deleted in this same PR, there is no longer a second pass that content-gates the first flag's value independently — the *entire* matched span, including the first (unsafe) value, is judged solely by the content of the trailing (safe) one.
  - Failure scenario: `git commit -m "$(rm -rf /tmp/important)" -m "Signed-off-by: x"`. The match spans both `-m` clauses; the trailing captured value is `"Signed-off-by: x"` (no `$(` / backtick), so the content gate at `_bdb_scrub` (lines 228-233) takes the *else* branch and replaces the **whole matched span** — including the `$(rm -rf /tmp/important)` payload — with a single space. `_cmd_match` (the only text every downstream destructive-pattern check operates on, per lines 264, 497, 558, 794-800) never sees the dangerous substring, so the hook that exists specifically to block `$(...)`-smuggled destructive commands silently lets this one through. This is a straightforward, realistic shape (git commits routinely carry a second `-m` trailer, e.g. `Co-Authored-By:`), not a contrived edge case.
  - Before this PR, the quote-excluded prefix forced the regex to bind to the *first* `-m`/value pair (a quote character in `"$(rm -rf ...)"` terminated the prefix match), so the dangerous value was content-gated on its own merits, and the (now-deleted) tail loop content-gated the second flag independently. Both changes together, not either alone, open the bypass.

- **HIGH** (confidence: high) `head/.claude/scripts/lib/invoke-diagnostics.sh:37,50` — The AWS key redaction pattern was narrowed from `(AKIA|ASIA|AROA|AGPA|AIPA|ANPA|ANVA)[A-Z0-9]{16}` to `AKIA[A-Z0-9]{16}` only. This drops redaction for `ASIA*` (STS/temporary session credentials — the default shape for assumed roles, AWS SSO, and GitHub Actions OIDC-to-AWS flows, arguably *more* common in CI diagnostic captures than long-lived `AKIA*` keys), plus `AROA*`/`AGPA*`/`AIPA*`/`ANPA*`/`ANVA*` (role/group/IAM-user identifiers). Any of these appearing in captured invoke diagnostics (this function exists specifically to scrub secrets before logs/diagnostics are persisted — see the function's own docstring) will now be written out in the clear. The PR description frames this as "trimmed back to the documented AWS access-key shape," but the code was *more* protective than the comment before this change; the correct fix would have been to expand the comment to match the code, not narrow the code to match an incomplete comment.

- **HIGH** (confidence: high) `head/.claude/scripts/workflow-state.sh:72` — `grep -c "^## Sprint [0-9]" "${SPRINT_FILE}" 2>/dev/null || echo "0"` double-prints when `sprint.md` exists but contains zero matching headers: `grep -c` writes `0` to stdout *and* exits with status 1 (GNU/POSIX grep exits nonzero whenever no lines are selected, independent of what `-c` printed), so the `||` also fires and appends a second `echo "0"`. The function's captured output becomes the two-line string `"0\n0"` instead of a single `"0"`. `get_completed_sprints()` (lines 78-94) does `total=$(get_total_sprints)` and then `for ((i = 1; i <= total; i++))` — evaluating a two-line string in bash arithmetic context is a syntax error, and this script runs under `set -euo pipefail` (line 16), so any caller hitting a `sprint.md` with zero `## Sprint N` headers (a normal state for a freshly created or malformed sprint plan) crashes instead of reporting `0/0` sprints. The `base/` version's `n=$(grep -c ... || true); echo "${n:-0}"` avoided this because the `|| true` only affects the exit status check for the assignment, and the final `echo "${n:-0}"` is a single, separate, always-singular print.
