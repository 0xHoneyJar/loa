- **HIGH** (confidence: high) `head/.claude/scripts/ledger-lib.sh:159` — The relaxed content check (`jq empty` instead of the previous `jq -es 'length == 1 and (.[0] | type == "object")'`) accepts multi-document JSON streams (e.g. `{"a":1}{"b":2}`), which the old check explicitly rejected via the `length == 1` guard. Downstream, `jq --arg ts ... ## Observations

- `head/.claude/scripts/ledger-lib.sh:159` and `:178` — `echo "$content"` replaces `printf '%s' "$content"` in both the guard check and the stamping step. In this codebase's bash (`set -euo pipefail`, no `xpg_echo`), this is benign for content that is valid JSON (which always starts with `{`, `[`, `"`, a digit, `t`/`f`/`n`, or whitespace — never `-`), but it's a needless reversion to a less-safe primitive for opaque string data; `printf '%s'` is the standard defensive idiom in this file (still used elsewhere, e.g. line 90) and the inconsistency invites a future copy-paste of the riskier form into a context where the leading-`-`/backslash hazard is live.

- `head/tools/check-no-swallowed-jq.sh:130-146` — The heredoc handling no longer distinguishes "executable heredoc piped to an interpreter" from "inert fixture/documentation text" (the deleted `hd_exec`/`_hd_command` heuristic). All heredoc bodies are now unconditionally skipped until their terminator (Step 1, lines 130-139). This simplifies the scanner considerably and fixes the stated false-positive problem (bats fixtures with planted bad examples), but it also removes the previous capability to catch the swallowed-jq anti-pattern when it appears inside a heredoc that *is* executed as a script (e.g., a gate script that assembles and runs an inline shell/python block via `<<EOF | bash`). None of the current `ENFORCED_FILES` were in this diff to confirm whether this path is live today, so this is a coverage-hole risk for future gate-critical scripts rather than a confirmed active miss — flagging as non-blocking given the tool is explicitly documented as "one tripwire layer, NOT exhaustive defense" (file header), but worth a follow-up note in the tripwire-scope caveats since it's a real capability given up, not just a false-positive fix.

## Overall Assessment

The stated goal ("lighter", "simpler", "fewer except clauses") is met literally, but two of the three simplifications quietly widen holes that the code they replace was specifically written to close, and both are independently verifiable rather than speculative: the ledger multi-document bypass reproduces the exact corruption class from bug 20260808-a008c6 (just via a different malformed-JSON shape), and the adapter change removes a documented, reachable crash guard with no compensating sanitization elsewhere. The heredoc-scanner simplification is a reasonable trade (fixes a real false-positive, loses a heuristic capability) and is left as an observation. Recommend reverting the `jq empty` relaxation back to a single-object check (or moving the guard to `jq -e` immediately after the stamping step, before the lock, so the "before touching lock/backup" invariant holds for every rejected shape) and restoring the `except ValueError` handler in the adapter.
