# Review: refactor(audit,spiral,semver): drop strict-verify plumbing, backtick masking and prerelease branches

## Changes Required

- **CRITICAL** (confidence: high) `head/.claude/adapters/loa_cheval/audit_envelope.py:462` — `_check_trust_store()` now unconditionally treats `BOOTSTRAP-PENDING` as a pass (`if status in ("BOOTSTRAP-PENDING", "VERIFIED"): return`), with no remaining way to require a fully-signed, verified trust-store. The deleted `strict_verify` parameter and its `[TRUST-STORE-BOOTSTRAP-PENDING] ... (ATK-3)` raise (base/.claude/adapters/loa_cheval/audit_envelope.py:479-483) were the merge-gate defense against ATK-3 — an attacker (or a broken install) presenting an unsigned trust-store during a merge-time verification would previously be refused; after this change, `audit_verify_chain()` called from any merge gate accepts an unsigned trust-store outright. The docstring on `audit_verify_chain` still claims "F1 (review remediation)" strip-attack protection is enforced, but that protection is only meaningful once the trust-store itself is proven to be signed — which this change removes the ability to require. This is a security regression, not a simplification, and needs either a design discussion or restoration of the strict path before merge.
- **HIGH** (confidence: high) `head/.claude/adapters/loa_cheval/audit_envelope.py:578` — `_resolve_pubkey_pem(kid)` now always falls through to the local `<key-dir>/<key_id>.pub` file (`head/.claude/adapters/loa_cheval/audit_envelope.py:141-166` region) even when a signature is being checked in a merge-gate/CI context. The removed `allow_local_fallback=not strict_verify` (base/.claude/adapters/loa_cheval/audit_envelope.py:609) existed specifically so that merge-time verification only trusts keys pinned in the trust-store, not a same-checkout `.pub` file that an attacker with write access to the working tree can drop next to the log. Combined with the `BOOTSTRAP-PENDING` finding above, chain verification during a merge gate can now be satisfied entirely with attacker-controlled local files.
- **HIGH** (confidence: high) `head/.claude/adapters/loa_cheval/audit_envelope.py:476` — `_read_trust_cutoff()` silently returns `None` on a missing or unreadable trust-store instead of raising `[TRUST-STORE-MISSING]` / `[TRUST-STORE-UNREADABLE]` (ATK-4, base/.claude/adapters/loa_cheval/audit_envelope.py:497-518). A `None` cutoff makes `_ts_ge_cutoff` return `False` for every entry (head/.claude/adapters/loa_cheval/audit_envelope.py:497-505: `if not cutoff or not ts_utc: return False`), so the F1 strip-attack check at `head/.claude/adapters/loa_cheval/audit_envelope.py:566` never fires for any entry when the trust-store can't be read — deleting/corrupting the trust-store file now silently disables the strip-attack detector this PR's own docstring says is still enforced, rather than failing closed.
- **HIGH** (confidence: high) `head/.claude/scripts/spiral-evidence.sh:702` — removing the `content_bare` backtick-stripping step (previously applied before Pattern 2's bare-path scan) reintroduces the exact false-positive class that the "#1175" guard comment two lines above (`head/.claude/scripts/spiral-evidence.sh:685-691`) documents and was written to fix. That guard's whitespace/glob/`-`/`@` filters only apply to Pattern 1's own match; Pattern 2 has no equivalent filter and previously relied on `content_bare` to exclude backtick-quoted example text (e.g. `` `bash .claude/scripts/foo.sh --verbose` ``) entirely. With `content_bare` gone, Pattern 2 will extract `.claude/scripts/foo.sh` straight out of that same backtick-quoted shell-command prose (the leading backtick and following space are non-path boundary chars, satisfying the anchor), so a sprint.md deliverables section that merely mentions an example command in backticks can again produce a spurious required-path entry and fail the cycle with `IMPL_EVIDENCE_MISSING` — the same failure mode #1175 fixed, just routed through the other pattern.
