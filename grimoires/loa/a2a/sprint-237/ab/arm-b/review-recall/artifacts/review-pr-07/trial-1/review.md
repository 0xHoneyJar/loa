# Review: chore(hooks,constructs): allow bounded hidden dirs, first-match local sources, strict traversal rejection

## Overall Assessment

Three independent changes bundled in one PR. The `block-destructive-bash.sh` hidden-dir allowlist fix and the `symlink-manifest.sh` traversal-rejection simplification are both correct and, if anything, tighten safety. The `constructs-lib.sh` change to `find_local_source` removes the only mechanism that ties a returned path to the requested construct slug, which breaks slug-safety for any config using `constructs.local_source_paths` with more than one entry. That must be fixed before merge.

## Changes Required

- **HIGH** (confidence: high) `head/.claude/scripts/constructs-lib.sh:565-591` — `find_local_source` no longer verifies that the returned path actually corresponds to the requested `$slug`; it now returns the first `search_paths` entry that merely contains a `construct.yaml` or `manifest.json`, regardless of which pack it is. This is safe for the *default* search paths (they already embed `$slug` in the path name, e.g. `$HOME/Documents/GitHub/construct-$slug`), but `config_paths` (`.constructs.local_source_paths[]`, line 571) is read as a single flat list with **no per-slug interpolation at all** — the exact same list is searched for every slug. Under the removed `_local_source_matches_slug` check, each candidate was filtered by directory name or the pack's declared `name`/`slug` field before being accepted; that filter is now gone. Concretely: a user with `local_source_paths: [~/dev/construct-alpha, ~/dev/construct-beta]` calling `find_local_source beta` will silently get `~/dev/construct-alpha` back (whichever entry sorts first and has a manifest), because the first loop iteration matches on directory existence alone and returns immediately. Since a "local source" is subsequently used to install/refresh a construct pack (which can include hooks and scripts that get symlinked into `.claude/`), resolving to the wrong pack means the wrong executable code gets installed under a name the user didn't ask for — a correctness bug with security-adjacent impact, not merely cosmetic. The slug-match filter (or an equivalent guard restricted to the config-path branch) needs to be restored, or `config_paths` needs to become per-slug (e.g. substitute `$slug` before the `yq` query) so a flat list can no longer alias across packs.

## Observations

- **LOW** (confidence: medium) `head/.claude/scripts/lib/symlink-manifest.sh:236-238,255-258` — Validation 2 now rejects *any* literal `..` segment in `target`, whereas the removed `_normalize_rel_path` resolution previously only rejected targets that actually resolved outside the repo root. A manifest with an in-bounds relative target such as `.claude/hooks/foo -> ../lib/shared.sh` (which stays under `.claude/` after normalization) would have passed before and is now unconditionally rejected. This is strictly more conservative (no security regression — if anything it's safer), but it is a behavioral tightening that could break previously-valid construct manifests using relative `..` references within `.claude/`. Worth a release note if any shipped construct manifest relies on that pattern.
- **LOW** (confidence: low) `head/.claude/hooks/safety/block-destructive-bash.sh:20-21` — The new hidden-dir allowlist protects only the *exact* sensitive names (`.git`, `.ssh`, `.aws`, `.kube`, `.gnupg`, `.docker`, `.config`, `.claude`, `.env*`); a lookalike such as `./.ssh-backup/` or `./.git-old/` is not covered by `_re_allow_exclude` and falls through to the new `\./\.[A-Za-z0-9_-][^*]*` allow branch, permitting `rm -rf` on it without confirmation. This mirrors the pre-existing design for visible directories (only exact names like `node_modules` are exempted, not prefixes), so it's consistent rather than a new hole, but it's worth confirming that's the intended trust boundary now that the hidden-dir surface is much larger than before.

## Verification Notes

- `block-destructive-bash.sh`: traced the new `_re_allow_exclude` / `_re_allow_list` regexes by hand against representative inputs (`./.loa/qmd`, `./.claude`, `./.claude2`, `./.git`, `./.env`, `./.ssh-backup`, `./..`, `./.`) — the named-exclusion set correctly blocks the System Zone (`.claude`) and credential/history dirs while letting other bounded hidden subdirs (e.g. `./.loa/…`) through, matching the PR's stated intent and the FR-2-AMBIGUOUS advice it's fixing. The pre-existing `_re_dotdot` check still runs before this list and continues to catch any `../` escape regardless of the exclude/allow lists.
- `symlink-manifest.sh`: confirmed `link` is still required to start with `.claude/` (Validation 1, unchanged) and absolute paths are still rejected (Validation 3, unchanged), so removing the normalize-and-resolve step does not open a new escape — `_path_has_traversal` on the raw `target` string catches every `..` occurrence unconditionally, which is a superset of what the removed resolution caught.
- `constructs-lib.sh`: no callers of `find_local_source` are included in this diff's touched-file set, so the blast radius (how many configs actually populate `constructs.local_source_paths` with multiple entries) couldn't be confirmed from the PR alone; the finding above is based on the function's own contract and the default-vs-config-path asymmetry visible in the code.
