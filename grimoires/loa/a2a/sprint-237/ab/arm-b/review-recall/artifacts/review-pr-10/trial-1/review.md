## Summary

PR fixes bug-725: `loa-doctor.sh`'s ajv version probe (`head/.claude/scripts/loa-doctor.sh:214-221`) used to run `ajv --version 2>&1 | head -1 || echo "unknown"`, which on ajv-cli@5+ (which dropped `--version`) captured the first line of a usage-error message and displayed it as if it were a real version string. The fix extracts a new `_loa_probe_ajv_version` helper (`head/.claude/scripts/loa-doctor.sh:228-261`) with a three-tier fallback: try `ajv --version` and validate the output looks like `X.Y[.Z]`, else parse `ajv --help` for a `version X.Y.Z` line, else fall back to a labeled placeholder `"unknown (ajv-cli@5+)"`. It ships with a new bats suite (`head/tests/unit/bug-725-ajv-version-probe.bats`) that exercises the real production function (extracted from the script via `awk`, not a hand-written replica) against hermetic stub binaries covering the v4 happy path, the v5+ `--help`-fallback path, the placeholder path, and two `set -eo pipefail` regression cases for the BB #916 F1 finding (grep-returns-1-under-pipefail aborting the caller before the placeholder is assigned).

## Code Review

- `head/.claude/scripts/loa-doctor.sh:245` — `ajv_ver=$(ajv --version 2>/dev/null) && [[ "$ajv_ver" =~ ^[0-9]+\.[0-9]+ ]]` correctly requires both a zero exit status and a version-shaped stdout before trusting the v4 path; stderr is dropped so a v5+ usage error written to stderr can't leak through as before.
- `head/.claude/scripts/loa-doctor.sh:252-256` — the `--help` capture (`ajv --help 2>&1 || true`) and the parse pipe (`grep ... | head -1 | awk ... || true`) are each independently pipefail-guarded, so a no-match `grep` (exit 1) can't abort the calling script under `set -e -o pipefail`. This is exactly the BB #916 F1 defect class and the guard is correct; tests `bug-725-9` and `bug-725-10` verify it end-to-end including the case where `ajv --help` itself exits non-zero.
- `head/.claude/scripts/loa-doctor.sh:218` — call site is unchanged in shape (`_doctor_add_check "optional_tools" "ajv" "ok" ... "$ajv_ver"`), so the surrounding `check_optional_tools` control flow and status handling for `br`/`sqlite3` are untouched — surgical, no incidental refactor.
- Test suite structure is sound: it sources the real function via `awk '/^_loa_probe_ajv_version\(\)/,/^}/'` rather than re-implementing the logic, so the tests actually validate the shipped code path (closing the BB #916 F-001 gap called out in the test file's own comments), and it includes an explicit anti-regression test (`bug-725-8-source`) that fails if the old `ajv --version 2>&1 | head -1` one-liner reappears on a code line.

## Observations

- **LOW** (confidence: low) `head/.claude/scripts/loa-doctor.sh:253-256` — the `--help` fallback assumes ajv-cli@5+'s help text contains a literal `version X.Y.Z` token; this assumption is only validated against hand-written stub fixtures in the bats suite, not against real `ajv-cli@5+` output (no such binary was available to verify empirically in this review). If real ajv-cli help text uses a different format (e.g. `ajv-cli 5.6.0` without the word "version", or the version only in `ajv --version`'s stderr banner), every v5+ install would silently fall through to the `"unknown (ajv-cli@5+)"` placeholder instead of surfacing the real version. This is a soft-degradation, not a crash or incorrect-data bug (the placeholder is honest about not knowing the version), so it's non-blocking — worth a quick manual `npx ajv-cli@latest --help` smoke test before/after merge to confirm the regex actually fires on real output.
- **LOW** (confidence: low) `head/.claude/scripts/loa-doctor.sh:245` — the v4-path regex `^[0-9]+\.[0-9]+` anchors to the start of the *entire* captured string (not per-line), so if some `ajv --version` implementation ever prints a preamble line before the version (e.g. a banner), the whole multi-line capture fails the regex and the code falls through to the `--help` parse instead of extracting the real version from the correct line. Low risk since ajv-cli v4's actual `--version` output is a bare version string with no preamble, but the fallback would silently produce a worse answer (or the placeholder) rather than surfacing the true version if this assumption breaks in a future ajv-cli release.
- Test file comments cite `BB #916` and `bug-899` as prior art for the extraction-from-source-via-`awk` pattern; not verified against those items directly, but the technique itself (extracting a single function bounded by `/^name\(\)/,/^}/`) is sound for this function because it contains no unindented `}` before its own closing brace.
