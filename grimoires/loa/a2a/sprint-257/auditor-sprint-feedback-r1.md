## Findings

### MEDIUM-A1 — under `local_voices` a local model's hosted fallback leaves the declared providers inside one cheval call (dissent DISS-C-001, confirmed)

`hop-locality.py` alone knows `fallback_chain_reaches_hosted`; the loader admits `qwen-leaky` (`dispatch_group: local`, `fallback_chain: ["openai:gpt-5.5"]`) — LOC-10's own output lists it — and `routing/chain_resolver.py` builds the chain from the model entry with no locality input, so the walk reaches `openai:gpt-5.5` with the hosted adapter's transport. The dissent script's planner filters its own chains (`_adv_locality_filter`), but Bridgebuilder's `localVoiceDecision` checks the voice's provider only, and cheval — the one process that actually sends the prompt — never reads `hounfour.locality`. SDD D-8.1: "every local hop is dispatched under the D-7.2 request-time rules … so a declared locality is enforced, not trusted" and "the repair chain stays on the declared providers".

Required: (a) `cheval.py` plans around locality the way `_plan_around_agy` plans around the agy opt-in: when the merged `hounfour.locality` is `local_voices`, every chain entry whose provider or endpoint host fails the local-hop rule (the loader's `local_endpoint_host` plus the `dispatch_group: local` label; a CLI entry is hosted) is dropped from the plan with one stderr line `locality: local_voices refuses hosted hop <provider>:<model> (fallback of <primary>)`; a chain left empty refuses the call with a typed error and a MODELINV row `failure_class: locality_refused` — never a silent reroute. (b) The loader refuses at load, only when `hounfour.locality` is `local_voices`, a `dispatch_group: local` model whose `fallback_chain` names an entry that fails the rule: `[CONFIG-INVALID] providers.<p>.models.<m>: under hounfour.locality local_voices the fallback_chain reaches a hosted hop <entry>` (under `hosted` a local model may still fall back to the cloud). (c) Bridgebuilder `localVoiceDecision` walks the voice's `fallback_chain` in the trusted view (depth-limited, cycle-safe) and reports `… dispatch_group local but its fallback_chain reaches hosted hop <entry>`; the trusted-config provider reader carries `fallback_chain`. Tests: pytest for (a) (a stub local server answers; a chain `[local, hosted]` under `local_voices` plans only the local entry and says so; `[hosted]` alone refuses with the MODELINV row; under `hosted` the chain is unchanged) and (b); LOC/FLL cases unchanged plus the loader case; `trusted-config.test.ts` for (c); `dist/` rebuilt.

### MEDIUM-A2 — Bridgebuilder's trusted configuration governs which voices it accepts, but cheval reads the checkout's configuration for the dispatch (dissent DISS-C-002, confirmed in its mechanism)

`adapters/cheval-delegate.ts:117-172` spawns `cheval.py` from `process.cwd()` with the inherited environment, and `loader.py` has no configuration-path override, so on a pull request the providers, aliases and `secret_env_allowlist` that the actual request uses come from the head checkout, while `loadTrustedConfig` compares the head only for keyless and insecure declarations. A head that re-points an existing provider's `endpoint` to a public `https` host, re-aliases a planned voice, or widens `secret_env_allowlist` and binds `auth: "{env:…}"` to it is not refused, and the first request carries the credential the environment holds. The built-in allowlist being extendable from the governed file is the documented design (`interpolation.py:25-27` keeps the defaults; the project list adds); the gap is the head.

Required: in pull-request mode `loadTrustedConfig` also compares the head's `hounfour.providers` (every field, endpoints and `auth` templates included), `hounfour.aliases`, `hounfour.locality` and `secret_env_allowlist` with the trusted source's; any difference is `headDrift` and `main.ts` refuses the multi-model run by name before any voice is planned — `trusted config drift refused: <key> differs between the PR head and <source>; merge the base branch into the head or set BRIDGEBUILDER_TRUSTED_CONFIG` — with a non-zero exit distinct from 3 and 4 (the callers already treat other exits as "did not complete"). Local mode (no PR) is unchanged. The example's `bridgebuilder` comment and the multi-model reference state that cheval reads the checkout's configuration and that the drift refusal exists for that reason. Tests: `trusted-config.test.ts` (an endpoint re-point, an alias re-point, an allowlist widening, an identical head → no drift; the refusal text) and the `main.ts` exit path if it is covered by a unit; `dist/` rebuilt.

### LOW-A1 — `localhost` is accepted as a local host but resolved by the system resolver (dissent DISS-C-004, confirmed)

The example's "never resolved, so no rebinding" is true of IP literals; `localhost` passes the rule by name and `urllib` resolves it through `/etc/hosts` and nsswitch. Required: `TransportPolicy.check_url` resolves a `localhost` request host with `socket.getaddrinfo` and refuses by name when any returned address is not loopback (fail closed; a resolver failure refuses too); the example comment says `localhost` is resolved and checked at request time. Test with a monkeypatched `getaddrinfo` (loopback → accepted; a public address among the results → refused; failure → refused).

### LOW-A2 — the one-family DEGRADED audit is not machine-readable (dissent DISS-C-005, confirmed)

Under `local_voices` with one local family the envelope carries the sentence in `metadata.locality.note` and `companion_voice.counted_as: duplicate_voice`, and nothing a gate can test. Required: `metadata.locality.degraded_security_review: true` on the audit envelope in that case (false otherwise when the key is present); LOC-4 asserts it; the auditing skill's prose names the field. `verdict_quality` and `verdict-derive.sh` are the floor and stay untouched.

### LOW-A3 — a zero price on a hosted model zeroes both the pre-call estimate and the ledger (dissent DISS-C-003, confirmed as a hardening)

A project overlay `pricing: {input_per_mtok: 0, output_per_mtok: 0}` on a hosted, non-`open_weight` entry estimates 0 and records every call at 0 as a `config` price. Required: `_adv_budget_estimate` WARNs by name when a zero-priced planned voice is not marked `open_weight` (`budget: zero price on <alias> (<role>), not marked open_weight — check the pricing overlay`) and a BUD case pins it; a follow-up bead records the metering-side guard (a zero price on a non-open-weight hosted entry counted as unpriced so the 5 % share trips) for the next cycle.

### Accepted by design — RFC1918 opt-in as an SSRF primitive (dissent DISS-001)

D-7.2's threat model admits an `http` endpoint on a loopback or RFC1918 IP literal only through a per-provider `allow_insecure_endpoint` naming that exact host in the operator's own configuration, and the probe reaches only that host (`model-health-probe.sh:1425-1499`). A repository-controlled configuration is the MEDIUM-A2 case and is closed there; no further change.
