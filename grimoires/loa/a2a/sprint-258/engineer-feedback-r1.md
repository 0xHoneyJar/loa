## Findings

**MEDIUM-1 — `Dockerfile.ablation` carries a dead build stage that fails under the legacy builder.** `evals/harness/Dockerfile.ablation:19-20` declares `FROM rust:1-bookworm AS brbuild` and `RUN cargo install beads_rust --version 0.2.6 …`, while line 82 explains that `br` is deliberately absent because that crate is not on crates.io. BuildKit (the default since Docker 23) skips an unreferenced stage, which is why the image built; `DOCKER_BUILDKIT=0 docker build` builds the stage and fails on the `cargo install`. The Dockerfile is the batch's version pin (DEC-0411) and must build the same way everywhere. Fix: delete the two lines; keep the line-82 comment. Add a bats case asserting the file has one `FROM` and no `cargo install`.

**MEDIUM-2 — `ablation-row.sh` hands every input to jq as an argv string and will hit `MAX_ARG_STRLEN` on the longest runs (DISS-C-003, confirmed).** `evals/harness/ablation-row.sh:226` passes the whole MODELINV ledger (`$MINV`, every line wrapped as `{line,row}`), `grade.json`, `pipeline.json`, the manifest, both dissent envelopes and the transcript write list as `--argjson` values. Linux caps one argument at 128 KiB. The smoke's largest `eval/model-invoke.jsonl` is already 28 KB for A1 on a trivial build task; a real task with Flatline, two gates and two fix rounds plausibly passes the cap, at which point `exec` fails with `Argument list too long` (exit 126, outside the 0/1/2 contract) and no row is written for exactly the most expensive runs. Fix: write MINV, PIPE, GRADE, MAN, the envelopes and DOT_WRITES to files under a `mktemp -d` and pass them with `--slurpfile` (or `--rawfile` + `fromjson`); keep `--arg` for scalars. Test: a fixture run whose `model-invoke.jsonl` is generated at > 200 KB produces a valid row.

**LOW-1 — the row-building jq program aborts on plausible field shapes and the script then exits outside its contract (DISS-C-001 confirmed as hardening; DISS-C-002 folded in).** `ablation-row.sh:230` `ms()` calls `fromdateiso8601`, which rejects a `+00:00` offset or an empty string; `:231` `voices()` indexes `.metadata.companion_voice.planned` and aborts when `companion_voice` is a boolean; `:247` runs `keys[]` on `models_used` and reports a spurious mismatch when it is an array. Today's producers do not emit those shapes (`pipeline-run.sh` writes `%Y-%m-%dT%H:%M:%SZ` and builds `models_used` with `with_entries` over an object), so this is hardening, but `ROW="$(jq …)"` under `set -e` turns any such abort into exit 5 with no row. Fix: `try … catch null` around the date parse, `objects`/`// {}` guards on `companion_voice` and `models_used`, writer defaults for `name`, `model_requested`, `models_used` and a boolean-or-null coercion of `verdict_accuracy` (so the writer always satisfies its own `--validate`), and `ROW=… || usage "row build failed for $RUN_ID"`. Test: a `pipeline.json` with `finished: ""` and an envelope with `companion_voice: false` still produce a row.

**LOW-2 — `spend.sh` under-counts silently (DISS-C-005, confirmed).** `evals/harness/spend.sh:159-160` reports skipped (unparseable) ledger or run rows on stderr only while the total prints as complete; `:135-139` dedups run rows first-seen per `run_id`, so a run re-rowed later (smoke row, then the graded row with its ledger cost) keeps the stale cost, and rows with an empty `run_id` are never deduped. For a cap tool the unsafe direction is under-counting. Fix: when `skipped_lines > 0` append `INCOMPLETE (N skipped)` to the text line, set `"complete": false` in `--json`, and exit 1; dedup keeps the maximum `cost_usd` per `run_id`; a row with no `run_id` is counted once per file with a stderr warning. Tests in `spend.bats`.

**LOW-3 — screen batches are excluded from the suite aggregate by directory name (DISS-C-006, confirmed).** `evals/harness/run-arms.sh:391` filters `! -path "$SUITE_DIR/screen-*"`; `STATUS.json` already carries `screen: true`, the authoritative marker. A regular `--batch screen-foo` is dropped silently and glob characters in `--results-dir` can defeat the exclusion. Fix: drop the `-path` filter and exclude inside the jq reduce with `map(select(.screen != true))`; refuse a `--batch` name starting with `screen-` unless `--screen` is set (exit 2). Tests in `run-arms.bats`.

**LOW-4 — `freeze.sh` neither hashes nor refuses symlinks (DISS-C-007, confirmed).** `evals/harness/freeze.sh:73` lists `find "$d" -type f`; a symlink under `tasks/` or `smoke/` is omitted from `MANIFEST.sha256`, so the frozen identity can change through a link target while `--check` keeps saying OK. Fix: list `\( -type f -o -type l \)` and refuse with exit 1 (`freeze: refused — the suite holds a symlink: <relpath>`) before hashing; also refuse a path with a newline. Test in `freeze.bats`.

**LOW-5 — the codex CLI version in the documentation drifted from the image.** `evals/harness/pipeline-run.sh:85` ("codex 0.137.0"), `CHANGELOG.md:17` ("codex 0.137.0") and `grimoires/loa/sdd.md:139` ("codex CLI 0.137.0") disagree with `Dockerfile.ablation` (`CODEX_VERSION=0.162.1`, the DEC-0485 / KF-044 repoint). Fix: the implementer corrects the pipeline-run.sh header; the lead corrects the CHANGELOG and the SDD row (noting the Sprint 258 amendment) at integration.
