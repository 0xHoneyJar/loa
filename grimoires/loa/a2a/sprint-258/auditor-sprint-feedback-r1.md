## Findings

**MEDIUM-A1 — the row writer trusts the dissent envelope inside the sandbox (DISS-C-001, confirmed).** `evals/harness/ablation-row.sh:215-216` and `evals/harness/took-effect.sh:87-88` read `sandbox/grimoires/loa/a2a/sprint-1/adversarial-<gate>.json` first and fall back to `eval/` only when the sandbox copy is absent; `pipeline-run.sh:776-777` re-copies `adversarial-*.json` from the sandbox into `eval/` after every phase, so a FIX or AUDIT phase that edits the REVIEW envelope overwrites the harness-side copy too. `degraded`, `degraded_reason`, `voices_run` and the `one_voice_planned` rule therefore rest on a file the model under test owns, while DEC-0413 already treats the sandbox as untrusted for the arm. For the review-catch tasks the agent reads a third-party PR body, the classic injection vector. Fix: `pipeline-run.sh` copies each gate's envelope into `eval/adversarial-<gate>.json` once, at the end of the phase that produced it (REVIEW → review, AUDIT → audit), never overwriting, and records `envelope_sha256` in that phase's record; the every-phase copy loop goes; `ablation-row.sh` and `took-effect.sh` read `eval/` first and the sandbox only when `eval/` has none (legacy fixture runs); when both exist and differ, `ablation-row.sh` records `zone_violations.envelope_mismatch: ["<gate>"]`. Tests: a fixture run whose sandbox envelope is tampered after the gate yields the eval/ values and the mismatch entry.

**MEDIUM-A2 — a trial that dies without a `result` event costs the spend ceiling nothing (DISS-C-002, confirmed).** `evals/harness/run-arms.sh:514` adds `.executor.total_cost_usd // 0` per collected row; a trial killed on timeout, lost in transport or malformed adds 0, and the `run_cap` reservation is released the moment it fails. A stalling model or a degraded network burns real spend on every attempt while `SPENT` stays near zero and `budget_gate` keeps launching: `--max-usd` is not the hard ceiling its header promises. Fix: in `collect()`, a row whose status is not `completed` and whose reported cost is missing or 0 charges `RUN_CAP` to `SPENT` (not to the arm's mean), `STATUS.json.spend` gains `assumed_cap_trials: N`, and the header says so. Test: a stub executor that fails without a cost under `--max-usd` drives the cut at the right trial.

**LOW-A1 — `execute-agent.sh` passes the arm's `effort` to argv without its own whitelist (DISS-C-003, confirmed as defence in depth).** `evals/harness/execute-agent.sh:268-269` overrides the validated `effort` with the raw toggle string; today `apply_arm_toggles` (the library) rejects anything but `low|medium|high|xhigh|max`, so the value is safe, but the guarantee lives in another file. Fix: re-validate `arm_effort` against the same `case` list (exit 2) in `execute-agent.sh`.

**LOW-A2 — self-modification through Bash is invisible to `zone_violations` (DISS-C-004, confirmed in part).** `ablation-row.sh` derives `dot_claude_writes` from Write/Edit/MultiEdit/NotebookEdit tool inputs only; `pipeline-run.sh` grants Bash, so `sed -i`, `cp` or a redirect into `.claude/`, `CLAUDE.md` or `.loa.config.yaml` leaves no entry. The `.claude/` tree itself is already covered after the fact by took-effect's `integrity_clean` (every manifest entry re-hashed), which the dissent did not see; `CLAUDE.md` and `.loa.config.yaml` are not. Fix: `pipeline-run.sh` records the sha256 of `CLAUDE.md` and `.loa.config.yaml` after materialisation (`arm_evidence` lines) and again at finish (`pipeline.json.mount_integrity: {claude_md, loa_config}` = `ok|changed|absent`); `ablation-row.sh` adds `zone_violations.bash_mount_refs` (Bash tool_use commands whose text matches `\.claude/`, `CLAUDE\.md` or `\.loa\.config\.yaml`, as `{phase, excerpt}` with the excerpt cut at 160 characters) and `zone_violations.mount_changed` from `mount_integrity`. `--validate` accepts the new keys.

**LOW-A3 — an inherited `LOA_ADVERSARIAL_REVIEW_ENFORCE` reaches the baseline executor (DISS-C-005, confirmed).** `execute-agent.sh:214` unsets it in arm mode only; a plain baseline eval run from a shell that exported `LOA_ADVERSARIAL_REVIEW_ENFORCE=false` runs with enforcement off and records nothing. `pipeline-run.sh` is unaffected (its environment is built from an allowlist). Fix: unset it in every mode before the toggles, let `apply_arm_toggles` set it only for `gates: false`, and record the final value (or `unset`) in `executor.json`.

**LOW-A4 — `fingerprint.sh` executes a path under one operator's home directory (DISS-C-006, confirmed; the review's O-4).** `evals/harness/fingerprint.sh:54` falls back to `~/.local/dotfiles/tools/diff-so-fancy/test/bats/bin/bats` when bats is not on PATH: a host-specific binary run with the harness user's privileges, undocumented in the fingerprint. Fix: drop the fallback; `bats` on PATH, `--bats-bin` or `LOA_EVAL_BATS_BIN`, else `absent`.

**LOW-A5 — the row's `arm` is not validated against the arm grammar (DISS-C-007, confirmed).** `ablation-row.sh` accepts any non-empty `meta/arm` or manifest `arm_map` value; `execute-agent.sh` and the mount library enforce `^[a-z][a-z0-9_]{0,63}$`. Fix: apply that pattern in the writer (exit 2) and in `--validate`.

**LOW-A6 — the image's Python dependencies and bats are not pinned (auditor).** `evals/harness/Dockerfile.ablation:67` installs `rfc8785>=0.1.4 jsonschema>=4.21 pyyaml>=6.0 httpx[http2]>=0.24.0` and `:70` clones bats-core by tag only; the image digest pins a batch, but a rebuild of the same Dockerfile can resolve different code. The image built on 2026-10-15 resolved `rfc8785==0.1.4`, `jsonschema==4.26.0`, `PyYAML==6.0.3`, `httpx==0.28.1`; the `v1.13.0` tag points at commit `3bca150ec86275d6d9d5a4fd7d48ab8b6c6f3d87`. Fix: pin those four exactly, add `ARG BATS_COMMIT=3bca150ec86275d6d9d5a4fd7d48ab8b6c6f3d87` and fail the build when the clone's `HEAD` differs; a grep-based bats case keeps `>=` out of the pip lines. The lead rebuilds the image from the pinned Dockerfile before Sprint 260's first batch and records the digest.
