## Findings

**HIGH-A1 — an agent-left pytest or bats harness file is loaded while the agent is graded (DISS-C-001, confirmed).** `prepare()` restores the `grader_protected` paths from the fixture and overlays the hidden files, but every other file of the agent's tree stays. pytest discovers `conftest.py` at any level under `--rootdir` and reads `pytest.ini`, `.pytest.ini`, `pyproject.toml` `[tool.pytest.ini_options]`, `setup.cfg` and `tox.ini`; a `conftest.py` the fixture never shipped (at the tree root, or at `tests/acceptance/` where the hidden tests overlay) can carry a `pytest_runtest_makereport` hookwrapper that turns every FAILED into PASSED and prints a parseable summary; `addopts = -p <module>` does the same from an ini file. bats auto-loads `setup_suite.bash` beside the test files. `validate-suite.sh` requires every `grader_protected` path to exist in the fixture, so the grader's "a path the fixture lacks is removed" branch never fires for a validated suite. Fix: before every `run_suite`, remove from the grading tree every harness or config file that is not byte-identical to the fixture's copy at the same path — `conftest.py` (any depth), `pytest.ini`, `.pytest.ini`, `pyproject.toml`, `setup.cfg`, `tox.ini`, `setup_suite.bash`, `*helper*.bash`, `.bats` `load`-able helpers under `tests/` and `test/` — and record the removed paths' count as `grade.json.harness_files_removed`; run pytest with `-o addopts=` and `-p no:cacheprovider` (already) so an ini-file `addopts` cannot inject a plugin; keep the fixture's own `conftest.py` (it puts `src` on `sys.path`). Tests: a sandbox with a root `conftest.py` hookwrapper that flips failures, a `tests/acceptance/conftest.py`, a `pyproject.toml` `addopts`, and a `tests/setup_suite.bash` → each is gone before the run, the hidden tests fail as they should, `harness_files_removed` counts them; the fixture's `tests/conftest.py` survives.

**MEDIUM-A1 — the grading container has no kill deadline, no resource limits and no cleanup (DISS-001, DISS-C-003, confirmed).** `exec_in_tree` runs `timeout 120 <cmd>` without `--kill-after`, so a test that ignores SIGTERM lives on; after `TEST_TIMEOUT_S + 60` Python SIGKILLs the docker client, which does not stop the container (`--rm` removes it only when it exits), leaving a live writer on `grading/<label>` that later steps re-read and `rmtree`; the run has no `--pids-limit`, `--memory`, `--cpus`, `--cap-drop ALL` or `--security-opt no-new-privileges`; stdout is captured unbounded into memory. `pipeline-run.sh` already does this right for the phases. Fix: `timeout --signal=TERM --kill-after=10 120`, `--init`, a deterministic `--name` with `docker kill`/`docker rm -f` on `TimeoutExpired` and on every error path, `--pids-limit 256 --memory 2g --cpus 2 --cap-drop ALL --security-opt no-new-privileges`, and a byte cap on captured output (read with a limit, truncate, record `output_truncated: true`). Test: the docker stub records the argv (deadline, limits, name) and a stub command that sleeps past the deadline is killed and reported `timed_out`.

**MEDIUM-A2 — the grader opens paths the agent's test process printed (DISS-C-002, confirmed).** `parse_pytest` takes node ids from `PASSED|FAILED|ERROR <node>` lines of the captured stdout, which the agent's code can print, and `def_line()` and the collection-error expansion open `os.path.join(tree, path)` on the host with no `safe_rel`/`is_within` check, no `lstat` and no size cap: `/dev/zero` exhausts memory, a FIFO created in `/workspace` during the run blocks `open()`, a symlink is followed, and the def line is a weak oracle on host files. Fix: validate every node path with `safe_rel` and `is_within(tree)`, open with `O_RDONLY | O_NOFOLLOW | O_NONBLOCK`, require `S_ISREG` and a size cap (1 MiB) via `fstat` before reading; prefer deriving the case order from the grader-owned hidden copies (`t.overlay` sources) and the fixture's protected test files, falling back to the tree only for paths that pass the checks. Test: a stdout line `ERROR /dev/zero` and one naming a FIFO leave the grader alive and the row intact.

**MEDIUM-A3 — agent files are copied and read without size bounds, and two readers follow symlinks (DISS-C-004, confirmed).** `copy_tree` `shutil.copyfile`s every regular file (a sparse `truncate -s 1T x` becomes a dense write on the host), `churn()` reads whole files, `combined_findings()` reads `review.md` and the feedback files whole, and `gate_verdict`/`review_md_verdict` iterate a file that may be one multi-GB line and do not reject symlinks (`combined_findings` does). Fix: `lstat` every source and skip files above 16 MiB (record `oversized_files_skipped`), read the verdict and citation files with a bounded read (first 2 MiB), reject symlinks consistently in every reader. Test: a 20 MiB sandbox file is skipped and counted; a symlinked `engineer-feedback.md` yields verdict `none`.

**LOW-A1 — `--executor host` runs the agent's tree on the grader host as the operator (DISS-C-005, confirmed as documented design).** DEC-0411 and the SDD record host mode as the fallback when the image cannot run; `env -i` strips the environment but gives no filesystem or process isolation, and `PYTHONUSERBASE` exposes the operator's user site. Fix: host mode refuses unless `LOA_EVAL_ALLOW_HOST_GRADING=1` is set (the self-check on the smoke tasks in CI's docker stub keeps working through `--docker-bin`), prints a WARNING naming the risk, and `grade.json.executor_mode: host` stays so a row is visibly host-graded. Not a sandbox of its own this cycle.

**LOW-A2 — the contamination scan exempts credential stores and misses `~/`, `$HOME/` and `/proc/*/environ` (DISS-C-006, confirmed).** `allowed_roots` whitelists `~/.aws`, `~/.codex`, `~/.claude.json` and `~/.claude` in host mode on the SDD's "the CLI's own configuration reads excepted" — but the CLI's internal reads never appear as `tool_use` events, so the exemption only shields an agent's `cat ~/.aws/credentials`. Fix: drop the credential stores from `allowed_roots` (keep nothing under `~` exempt), extend `ABS_WORD` to `~/` and `$HOME/` prefixes, flag `/proc/<pid>/environ|cmdline` and `/var/run` explicitly, and do not skip a `/x/` word when it is followed by a path-shaped continuation. Test cases in AG-10.
