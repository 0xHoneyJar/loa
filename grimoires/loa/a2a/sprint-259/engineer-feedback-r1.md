## Findings

**HIGH-1 — the grader follows agent-controlled directory symlinks when it deletes a grading tree, changing permissions outside the tree (DISS-001, confirmed).** `evals/harness/ablation-grade.sh` `copy_tree` recreates every symlink of `sandbox/` (`os.symlink(os.readlink(sp), dp)`, directory symlinks included) into `grading/final`; on the next grading of the same run `fresh_dir` → `remove_path` walks the tree and `os.chmod(os.path.join(r, d), 0o700)` on every entry of `ds` — `os.walk` lists a symlinked directory in `ds` even with `followlinks=False`, and `os.chmod` follows it. The grader runs on the host as the operator: a sandbox symlink the agent created in the container (`ln -s /home/merlin/Documents x`) is a string until the host grader resolves it, then its target gets mode 0700. `shutil.rmtree` itself does not follow symlinks, so the exposure is the chmod, but that is enough. Fix: `remove_path` never chmods through a symlink (skip `os.path.islink` entries; chmod only real directories); `copy_tree` drops a symlink whose target is absolute or resolves outside the destination tree (record `symlinks_dropped: N` in `grade.json`) and keeps only in-tree relative links; `extract_snapshot`'s tar filter already rejects escaping members — add the same rule for symlink members (`tarfile.data_filter` does, confirm with a test). Tests: a sandbox with `evil -> /tmp/<probe dir>` graded twice leaves the probe's mode unchanged and `evil` absent from `grading/final`; a relative in-tree link survives.

**MEDIUM-1 — for refactor tasks the primary metric reads the fixture suite, not the structural assertion (lead).** `grade()` puts `test_command`'s result into `hidden_tests` for every build type; D's refactor tasks set `test_command` to the fixture suite (ignoring `tests/structure`) and `regression_command: null`, so `hidden_tests` is the suite (green at base by construction) and the structural check lives only under `structural`. `ablation-row.sh` derives `hidden_test_pass_rate` from `hidden_tests.passed / total`: a refactor run that never touched the code scores 1.0 on the primary. DEC-0401 and AC-5.3 make the structural assertion the refactor task's hidden test. Fix: for `type: refactor`, `hidden_tests` = the structural check on the final tree, `regressions` = `test_command` at base vs final (`newly_failing`, `base`, `final`), `snapshot_tests` and per-gate accuracy use the structural command on the gate's snapshot (accurate when APPROVED and structural green and suite green, or CHANGES_REQUIRED and either red); `structural` stays for the self-check; header, README refactor paragraph, AG-7 and an AG-18-style case (grade then row → `hidden_test_pass_rate` equals the structural pass rate) updated. The self-check criteria are unchanged in substance (base: structural red, suite green; reference: both green).

**MEDIUM-2 — D's eight tasks protect only `tests/conftest.py`, so an agent can edit the regression suite it is graded against (lead; the R2 fairness notes raised it as advisory).** `grader_protected` on `bugfix-01…04` and `refactor-01…04` lists `tests/conftest.py` alone while the fixture test files (`tests/test_pages.py`, `tests/test_render.py`, `tests/test_layers.py`, `tests/test_tags.py`, `tests/test_resolve.py`, `tests/test_ledgerio.py`, `tests/test_report.py`, `tests/test_fetchq.py`, `tests/test_jobboard.py`) are the regression check; E's tasks protect every fixture test file (DEC-0506). Fix: add them; make `validate-suite.sh` enforce "`grader_protected` lists every file under `fixture/tests/`" for build tasks with a VS case, so the freeze cannot regress it; re-freeze.

**MEDIUM-3 — a parsed passing summary overrides a failing or timed-out command (DISS-002, confirmed).** `run_suite` returns the parsed counts whatever `rc` and `timed_out` are, and `all_pass` reads neither, so a bats run that prints a complete passing TAP block and then fails (a teardown error, exit 1), or a pytest run that prints its summary and exits non-zero, is green. Fix: `all_pass` requires `rc == 0` and `not timed_out`; `summary()` records `rc` and `timed_out`; the self-check and the per-gate accuracy use `all_pass`. Test: a stub command printing `1..1\nok 1` then `exit 1` is not a pass.

**LOW-1 — `bugfix-02`'s discarded-store case is red at base only probabilistically (lead).** `tests/test_memo_freshness.py::test_a_new_store_never_sees_a_discarded_one` loops fifty `Store` allocations and relies on CPython reusing `id()`; D records it as "not counted in the five deterministic reds". A hidden test whose base outcome varies adds noise to the primary. Fix: make it deterministic (force the id reuse with a bounded retry and `gc.collect()`, or assert the memo is keyed by object identity through a weakref) and show ten consecutive base runs red; update `success_criterion` counts if they change.

**LOW-2 — a regression command without a pytest or TAP summary can never report a newly failing case (DISS-003, confirmed).** With `parse_error` on the base run `base_ok` is `[]`, so `newly_failing` stays empty even when the final run fails. None of the sixteen tasks uses such a command (every `regression_command` is pytest or bats), so this is hardening for the allowlisted `bash`/`node` shapes. Fix: when either side is unparseable, derive `newly_failing` from the fallback ids and the exit statuses (base `rc == 0`, final `rc != 0` → every fallback id), and record `regressions.parse_error: true`.
