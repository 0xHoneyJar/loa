## Changes Required

### 1. The byte-identical guarantee can be bypassed (dissent DISS-001, DISS-C-002, DISS-C-001)

- **MEDIUM** (confidence: high) `evals/harness/seed-corpus-from-record.sh:387-392` — the new labels content is written to disk first and the original restored only when `build_manifest(fx, write=False)` returns a different JSON; a `fail()` (SystemExit) or any exception inside the rebuild — a generated `must_match` that `read_labels` rejects, a fix row the sync skipped without validating, a malformed `fixture.yaml` — leaves the half-synced file behind, which contradicts the header's "refuses … labels left unchanged". Separately the verification runs only when `new != raw`, so a no-op sync never proves the labels rebuild the manifest (a curator's edit to severity or category passes silently).
**Required Fix:** verify before writing (build from the new content in memory or from a temp path), write the labels only after the byte-identical check passes, and make any exception leave the file untouched; run the verification on every sync, no-op included. Tests: a sync whose rebuild fails exits 1 with the labels byte-identical; labels with every anchor row but a changed severity → `--sync-labels` exits 1 naming the mismatch.

### 2. Text beginning with `@L` cannot be anchored (dissent DISS-C-003)

- **LOW** (confidence: high) `evals/harness/seed-corpus-from-record.sh:243-253` — any `must_match` starting with `@L` is routed to the line grammar and refused when it is not `@L<digits>`, so a head line whose text starts with `@L` (Java/Kotlin annotations such as `@Lazy`, `@Lob`) can no longer be anchored by text and the curator sees a misleading grammar error.
**Required Fix:** only the exact `@L<digits>` form is the explicit line; digit-ish malformed shapes (`@L0`, `@L-1`, `@L4x`, `@Lx`) keep the grammar error SC-10 asserts; longer text starting with `@L` is ordinary text. Test: a head line `@Lazy foo` anchored by text.
