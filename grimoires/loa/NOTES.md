## Observation — 2026-07-05 (skill-loop pass 5, beads-health missing-owner detection latent defect)

- **Finding**: `.claude/scripts/beads/beads-health.sh` `check_schema()` can NEVER report `missing_owner` / MIGRATION_NEEDED: `has_owner=$(sqlite3 … "PRAGMA table_info(issues);" | grep -c "owner" || echo "0")` — when the owner column is absent, `grep -c` PRINTS "0" AND exits 1, so `echo "0"` appends a second zero and `has_owner` becomes the two-line string `0\n0`. Found by pass-5 differential testing (staging/pass5/tools/run-diff-pass5.sh, case bh-noowner-quick-json). Same double-zero shape also fires when sqlite3 itself fails.
- **Status**: DELIBERATELY PRESERVED in the pass-5 spawn-reduction rewrite (the `grep -c … || echo "0"` line is untouched) — the perf pass is behavior-identical by contract.
- **Follow-up**: needs its own test-first /bug cycle: `grep -c` already prints the count on no-match, so the `|| echo "0"` is the bug (`|| true` or dropping the guard entirely fixes it); exit-3 schema-migration detection for missing owner would then actually fire for pre-owner beads databases.
