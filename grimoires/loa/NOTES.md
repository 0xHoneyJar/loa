## Observation — 2026-07-05 (skill-loop pass 4, settings-cleanup latent defect)

- **Finding**: `.claude/hooks/hygiene/settings-cleanup.sh` post-cleanup secret scan could NEVER detect the `'-----BEGIN .* PRIVATE KEY'` pattern: `grep -qP "$pat" || grep -qE "$pat"` passes the pattern as the first argument without `--`, so the leading-dash pattern is parsed as grep OPTIONS → rc=2 (silenced by 2>/dev/null) → reported as no-match on GNU and BSD grep alike. Found by pass-4 differential testing (staging/pass4/tools/run-diff.sh, case sc-privkey-in-deny-preserved-defect).
- **Status**: DELIBERATELY PRESERVED in the pass-4 jq rewrite (leading-dash patterns report no-match) — the perf pass is behavior-identical by contract.
- **Follow-up**: needs its own test-first /bug cycle: make the scan actually warn on remaining private-key material (the jq scan can simply drop the leading-dash guard; a grep-based fix would be `grep -qP -e "$pat"`). Note the main filter (which REMOVES such entries from permissions.allow) was never affected — only the post-rewrite warning scan.

## Observation — 2026-07-05 (skill-loop pass 5, beads-health missing-owner detection latent defect)

- **Finding**: `.claude/scripts/beads/beads-health.sh` `check_schema()` can NEVER report `missing_owner` / MIGRATION_NEEDED: `has_owner=$(sqlite3 … "PRAGMA table_info(issues);" | grep -c "owner" || echo "0")` — when the owner column is absent, `grep -c` PRINTS "0" AND exits 1, so `echo "0"` appends a second zero and `has_owner` becomes the two-line string `0\n0`. The follow-up `[[ "${has_owner}" -eq 0 ]]` is then a bash arithmetic syntax error (stderr: `[[: 0\n0: syntax error in expression`) which evaluates FALSE, so the code falls through to `schema=compatible` and a no-owner database reports `"status": "HEALTHY"`, exit 0. Found by pass-5 differential testing (staging/pass5/tools/run-diff-pass5.sh, case bh-noowner-quick-json). Same double-zero shape also fires when sqlite3 itself fails.
- **Status**: DELIBERATELY PRESERVED in the pass-5 spawn-reduction rewrite (the `grep -c … || echo "0"` line is untouched) — the perf pass is behavior-identical by contract.
- **Follow-up**: needs its own test-first /bug cycle: `grep -c` already prints the count on no-match, so the `|| echo "0"` is the bug (`|| true` or dropping the guard entirely fixes it); exit-3 schema-migration detection for missing owner would then actually fire for pre-owner beads databases.
