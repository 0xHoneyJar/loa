head/evals/harness/ablation-report.py:1081 — HIGH: the grader_version tally sort key mixes int and str elements (`[int(p) if p.isdigit() else p ...]`), so if any run directory's grade.json carries a version with a non-numeric dot-component ("dev", "1.2.13-rc1", "1.2.x" next to "1.2.5"), the whole report dies with an uncaught TypeError instead of a Fail/exit 2. Reproduced: adding `{"grader_version":"dev"}` beside a "1.2.5" grade in the `present` fixture crashes ablation-report.py. That breaks the header's promise that the batch record is "never fatal", and it lets an informational section stop every decision from being written. Use a total-order key (e.g. a (kind, value) tuple per component).
head/evals/harness/ablation-report.py:1063 — MEDIUM: the batch record's grader tally is counted per row × matching directory, not per run directory. Each row matches every `<task>-t<n>[-r<k>]` directory of its cell, so one row counts both a stale t1 grade and its t1-r1 rerun, and a superseded row plus its retry count every directory twice. Reproduced: one extra rc-01-t1-r1 dir gives `1.2.5 ×2` for a single row, and adding a superseded transport_error row for the same cell inflates the tally again (and `trials_rowed` at :1003 counts rows, so it reads 19 for 18 trials). Count each directory once per batch, or map each row to its own run dir by run_id/attempt.
