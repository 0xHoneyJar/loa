head/.claude/adapters/loa_cheval/metering/pricing.py:168 — The long-context premium only fires when `input_tokens > threshold`, and this module's own docstring says `input_tokens` excludes the Anthropic cache read/creation tokens. head/.claude/adapters/cheval.py:2256 — `_ceiling_unverified` is computed once, for the HEAD entry's pre-flight, but this branch reads it on every hop of the walk. A fallback hop that is well under its own probed bound gets a provider context refusal labelled `CEILING_UNVERIFIED_LIMIT`, and that wrong class is what gets written to the observed store and the envelope. The flag needs to be per hop (derived from that hop's entry and budget).
head/.claude/adapters/cheval.py:2297 — Same per-head flag problem, and it changes routing: once the head dispatched in the opt-in unverified zone, a plain 429 from ANY later fallback hop (which was never above a probed bound) returns `RATE_LIMITED` instead of walking.
