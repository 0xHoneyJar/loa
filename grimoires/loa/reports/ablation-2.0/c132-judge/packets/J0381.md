head/.claude/scripts/lib/dec-write-lib.sh:642 — `import` appends pending rows verbatim. The only checks are that ids match PEND-<8 hex> and that the validator passes, and the validator does not require new rows to enter as open/proposed. So a pending file (agent-written, in a worktree) that holds a row with `status: decided`, `decided_by: operator`, `decided_by_ref: cli:…` and a proposed→decided transition `by: operator:decisions-command` lands in the live ledger as an operator decision without `/decisions confirm` ever running. Reproduced: `import --from …/decisions-pending.yaml` gave `DEC-0001 decided operator`. Import must refuse any row whose status is not open/proposed, whose decided_by is not null, or that has more than one transition.
head/.claude/scripts/validate-artifact.sh:686 — The append-only check limits only rows already in the base. A row absent from the base is checked only against `decided_by operator` under a live unattended signal. Nothing stops a new row arriving with several transitions, already `decided`, or with `decided_by` set (the "more than one transition appended in one write" rule at :671 covers base rows only). This is the gap that lets import, or a hand edit checked with --base-file, create decided rows. Unless the file is a fixture import, new rows should carry exactly one transition, null -> open|proposed, and `decided_by: null`.
