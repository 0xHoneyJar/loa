head/.claude/adapters/loa_cheval/providers/agy_headless_adapter.py:125 — [high] With the opt-in off by default, every stock Google fallback_chain still ends in `google:gemini-headless`. So when the HTTP hops fail with walkable errors (rate limit, 5xx, disconnect), the walk reaches the agy terminal, and `AgyOptInRequiredError` (a non-retryable ChevalError) goes to cheval's hard-abort arm (cheval.py:2544). The call then exits INVALID_CONFIG "agy headless route is opt-in", with `retryable: false`, and the real retryable provider failure of the earlier hops is hidden. On a host with agy installed this is a new regression for every Google call, by default. The walk should treat a hop that is not opted in as not planned: skip it (record it as such) and surface `_last_walk_exception`. It should not abort the chain with a config error.
head/.claude/adapters/cheval.py:2544 — [medium] The PR presents `failure_class: opt_in_required` as "the machine-readable seam planners read as 'not planned'" (types.py:507) and the migration doc promises it on the cheval refusal. The failure_class never reaches stderr JSON or MODELINV, so no planner can tell opt_in_required apart from any other INVALID_CONFIG. Pass `**_e.context` (or failure_class) into `_error_json` and the models_failed record, and add a test that runs it  …
