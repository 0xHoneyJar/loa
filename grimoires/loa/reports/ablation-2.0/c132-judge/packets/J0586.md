## Finding

``` text
head/.claude/scripts/lib/dec-write-lib.sh:642 — `import` appends every pending row as-is, after validating the pending file with no base file (line 627). It never checks that an imported row is still `open`/`proposed` with an agent-only history. A hand-edited `decisions-pending.yaml` holding `status: decided`, `decided_by: operator`, `decided_by_ref: cli:…` and an `operator:decisions-command` transition gets imported into the live ledger with exit 0 (reproduced in a scratch project: the result is DEC-0001 decided/operator). This bypasses the "a row becomes decided only through /decisions confirm" invariant the whole PR rests on. Import should refuse any row whose status is past proposed, or that has an `operator:` transition or a non-null `decided_by`.
head/.claude/scripts/validate-artifact.sh:686 — The append-only check limits only new rows with `decided_by: operator`, and only while a live unattended signal holds. A row that is new relative to `--base-file` / the merge-base can arrive already `decided`, with any number of transitions and operator attribution, and still pass. That is what lets the `import` bypass above, and a hand-appended ledger row, through the gate. New rows should be required to have exactly one transition (null -> open|proposed) and `decided_by: null`, or at least to have no operator-attributed transition.
```
