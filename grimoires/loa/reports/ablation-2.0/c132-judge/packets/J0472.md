## Finding

``` text
head/.claude/scripts/lib/dec-write-lib.sh:627 — `import` checks the pending file only with the plain schema validator (no base file, so it never compares against `proposed`), and nothing afterwards limits the imported rows to `open`/`proposed`. A pending file edited by hand to hold a `decided` row with `decided_by: operator`, a `cli:` ref and an `operator:decisions-command` transition gets imported into the live ledger as DEC-0001, decided by the operator. I reproduced this. That gets around the rule that only `/decisions confirm` makes a row `decided`. Pending files are written in linked worktrees by agents, so they are not trusted input. `import` should refuse any row that is not open/proposed, has a non-null `decided_by`, or has a transition past `proposed`.
head/.claude/scripts/lib/dec-write-lib.sh:513 — `confirm` refuses only live-run signals (line 509), but it then calls `derive_attribution`, and that function uses `is_unattended`, which also counts the PRD `**Status:** … autonomous` line. The PRD keeps that line after the run ends, so while it is there the operator's `--answer-ref cli:…` is dropped with a misleading WARN ("the row stays proposed"). The row is then confirmed with `decided_by: agent` and `decided_by_ref: null`. I reproduced this. Operator confirmations made through `/decisions` are recorded as agent decisions with no way to fix them, because the ledger is append-only.
head/.claude/scripts/lib/dec-write-lib.sh:575 — Same cause in `reject` and `supersede`  …
```
