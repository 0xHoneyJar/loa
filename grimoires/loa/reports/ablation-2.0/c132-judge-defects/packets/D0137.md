head/.claude/skills/bridgebuilder-review/resources/config.ts:684 — The head-only check only asks whether `keyless` / `insecure` are set, not what they point at. A PR head can keep a trusted provider's keyless/insecure flags and change its `endpoint`, its `allow_insecure_endpoint` host (any other loopback/RFC1918 address) or its `auth: "{env:VAR}"`, and it is not refused. cheval then dispatches with the head's working-tree declaration, so the prompt (or a credential) goes to a host the attacker picked. That breaks the D-7.5 claim that provider declarations come from trusted config only. Compare the whole declaration (endpoint, opt-in host, auth) with the trusted one, or refuse any head declaration that differs from it.
head/.claude/skills/bridgebuilder-review/resources/config.ts:482 — `literalAuth` makes any non-template `auth` string keyless, e.g. `auth: "sk-live-..."`. The Python side, `endpoint_policy.KEYLESS_AUTH_LITERALS`, deliberately accepts only `"local"` because "any other literal could be a real key". Bridgebuilder and cheval now disagree on which providers are keyless: Bridgebuilder marks a literal-key provider valid with no credential check, while cheval sends that literal as a Bearer token. Restrict this to `"local"` (case-insensitive, trimmed) to match D-8.0.
