## What shipped

**Sprint 281 — the optimisation loop through the formal gates.** A 22-pass `extreme-software-optimization` skill loop (2026-10-27/28) produced 20 commits over 18 System Zone files; every pass was profiled first, kept output byte-identical old-versus-new on golden and adversarial fixtures and passed a fresh-context review, and this sprint took them through `/review-sprint` and `/audit-sprint` with two-voice dissents (both consensus APPROVED). Headline numbers on the reference host (hyperfine, serial, idle): the repo-map generator 4658 → 1219 ms (one engine run, pre-sorted PageRank edges, a file→definitions index, list-indexed ranks); grimoire-index 1819 → 826 ms (one awk per family, one jq for the markdown); the SessionStart known-failures hook 488 → 15 ms (one awk sanitises and formats); the Write/Edit PreToolUse chain ≈ 78 → 62 ms (one jq per hook, lazy `compat-lib` probes); the Stop guard 24 → 14 ms (one yq for the push config); cheval imports one provider adapter instead of ten. A deterministic spawn-budget test (`tests/unit/perf-spawn-budget.bats`) guards the hot paths — and the gates hardened it twice before it shipped: it now traces through a dedicated descriptor so spawns behind stderr redirects and in child shells are counted, and it runs the hooks under an explicit environment and refuses live-state reads.

**Sprint 282 — the loop's six follow-ups.** Every bead landed red-first (a failing test commit, then its fix) with old-versus-new parity re-derived by the lead on the live tree, and the review and audit ran on the head that merges. **bd-atk7q** — the KF parsers (`loa-kf-surface.sh`, `grimoire-index.sh`) recognise `**Symptom (qualifier)**:` and `**Recurrence count (qualifier)**:` (not `Status`, whose live qualified form is a historical annotation), every `## ` heading closes the current entry, and a drift test pins the two parsers line for line; mawk and busybox awk agree byte-for-byte. **bd-1mfm7** — the grimoire index caches the decisions family in `.run/perf-cache/grimoire-index-decisions.v1.tsv`, keyed by one snapshot's sha256 plus the yq/jq versions and the row count, validated in one awk pass, written atomically, read and written only inside a trust boundary (real, uid-owned, not group- or world-writable directories; a uid-owned group-writable directory is tightened first; `LOA_GRIMOIRE_INDEX_NO_CACHE=1` and CI opt out); write mode 826 → 196 ms warm on the live tree; the write-mode checks come from one root-preserving jq. **bd-gv5jf** — `loa-status.sh` reads the six model-catalog fields with one yq (six-line protocol, verbatim fallback) and `agy-gate-lib.sh` memoises the opt-in node behind a file-identity key (dev:ino:size:mtime:ctime + PATH): −104 ms per `/loa` on the reference host. **bd-h5tcn** — `profiles.yaml` gains `cached_keys`; `loa_knob` answers an absent cached key without a live yq read, so the karpathy PostToolUse hook spawns no yq on the warm path. **bd-09z1i** — `audit-envelope.sh verify-chains` runs one Python process for every chain file, prints one JSON record per path in argument order and fails closed on a missing, duplicate or malformed record; the trust store is still checked per path (a store-mutation equivalence test proves N paths in one process equal N calls); `loa-status.sh` makes one call (`python3` spawns 5 → 1; about −1.15 s on a five-chain root). **bd-wctli** — `block-destructive-bash.bats` replays the fence corpus once per file (95 → 62 s), and `adversarial-review-companion.bats` bounds its reaped stub holds at twice the longest wait with a negative control per affected test; its remaining time is the script's own runtime (163 `main` runs), recorded as the measured floor by decision row rather than a quarantine.

## Deferred

None of the six beads was deferred. Recorded floors and residuals: the companion test file's wall time is its script's runtime (DEC-1130), not a test defect; BWK one-true-awk and BSD `cut` behaviour of the KF sanitiser is unverified on the reference host (MED-001 → bd-aceil); zone-write-guard still creates `.run/perf-cache` under the user's umask (bd-20bh1; the cache tightens it); the KF sanitiser lets UTF-8-encoded C1 controls through (bd-z6gxn); CMP-55 cannot yet prove its reaped hold (bd-rq6gk); the cheval provider registry's dispatch mapping, a bats helper's multi-tool skip list, a KF row cap and a karpathy trajectory symlink guard are the Sprint 281 observations (bd-0h7kq, bd-3qed8, bd-4sikh, bd-kdzc3).

## Revert paths

Every optimisation pass and every Sprint 282 bead is one fix commit (with its red test commit); a pass reverts alone after checking the later passes that share its helpers (`compat-lib.sh`), and `.claude/checksums.json` plus `grimoires/loa/REPO-MAP.md` are regenerated in the revert. The decisions cache is content-keyed and never fatal: `LOA_GRIMOIRE_INDEX_NO_CACHE=1` opts out, deleting `.run/perf-cache/grimoire-index-decisions.v1.tsv` is a plain miss. `verify-chains` leaves the singular `verify-chain` untouched; `loa-status.sh` is the only caller that switched.
