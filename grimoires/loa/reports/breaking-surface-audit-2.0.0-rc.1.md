## 3. How this rc is cut (Phase A answer)

Without sprint-bug-240, a merge of PR #1266 prepared `v2.0.0` (`semver-bump.sh` had no release → prerelease transition; `bump_version` `main:129-130` called it "operator-driven"), `phase_version_bump` would have stamped `2.0.0` over the markers, and `phase_release` posted no `prerelease` flag (`main:post-merge-orchestrator.sh:1104`). With it: the topmost CHANGELOG heading `## [2.0.0-rc.1] — …` (this PR) is untagged and its release triple equals the computed `2.0.0`, so `semver-bump.sh --from-tag` reports `next: 2.0.0-rc.1`, `prerelease_transition: {kind: enter}`; the prepared candidate carries `tag: v2.0.0-rc.1`, `prerelease: true`; `--publish … --approve-sha256` creates the tag and a GitHub release with `prerelease: true` and verifies the flag on read-back. The next merge on the rc tag prepares `2.0.0-rc.2`; promotion is a PR whose topmost heading is `## [2.0.0] — …`. Runbook: `grimoires/loa/runbooks/post-merge-candidates.md` §Pre-release candidates.
