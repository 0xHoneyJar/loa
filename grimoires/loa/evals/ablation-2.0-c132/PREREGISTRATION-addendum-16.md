## What the final read showed

The first `--final` read on the Phase 1 rows printed `frozen_c131_labels` and `v1_labels` as `not_provided`, because no re-grades under those keys existed. It had no branch at all for §10's second item, the seeded review-derived key over all 14 fixtures. It also printed the cost per extra defect against the matched arm as a negative ratio with status `ok`, and it omitted the §5 co-reads that every look prints. §5 defines that ratio only when both the defect increment and the cost increment are positive, and says to print anything else as dominated or dominated-by-cost with both increments (DEC-0805, DEC-0809).

## What changed

- **Review-derived key sensitivity.** `reads.py` gains `review_derived_labels`. It reads re-grades from the `review` label directory and sits right after `v1_labels`, the order §10 lists. The key is `manifests/review/` for pr-19 … pr-28. For pr-11, pr-14, pr-15 and pr-16 it is `manifests/c131/`, which the corpus seeder documents as the moved review-derived set. The three label sensitivities also print each arm's caught and labelled defects on the valid pairs, plus the counts of re-graded cells and cells without a re-grade. A frozen key covers four PRs, below the six-PR minimum, so those reads print `too_few_prs` beside these descriptive figures.
- **The dominated label.** The cost per extra defect reads `ok` only when both increments are positive. More defects at no more cost reads `dominated`. More cost for no more defects reads `dominated_by_cost`. In both cases the value is null and the report prints both increments. Every other number in the final read is byte-identical apart from the new co-reads. On the Phase 1 rows only the two matched cost-per-extra-defect entries change, from `ok` with −3.127 and −5.012 to `dominated` with a null value. The extra defects stay at 17 and the cost increments at −53.16 (valid pairs) and −85.21 (all spend).
- **Re-grade procedure.** `regrade_labels.py` produces the re-grades the label sensitivities read. For each label set, it copies the suite root, re-points `review_catch.manifest` for every task the set has a key for, and freezes the copy with `freeze.sh`. Every re-grade therefore runs under a frozen root. The script never grades a recorded run directory, because the grader rewrites `grading/` beneath the run directory even with `--out`. Instead it grades a hard-link copy of each cell, without the copy's `grading/` and `grade.json`. It uses `ablation-grade.sh` at the pin with the container executor: each matched session first, then `--union` per matched cell. It refuses a grade whose `label_set` is not its key's directory, and it refuses mixed grader versions.
- **Co-reads at the final.** §5 says the co-reads are reported beside the primary at every look and at the final, but `--final` never computed them; only `--look` did. The final read now carries them over every group, which is the final look. That covers the pipeline-independent Δ, recall per arm by `label_source` and `review_driven`, and the cost-matched Δ with its dollar-matching table. They appear under `co_reads` in the JSON and as a section after the pre-registered reads and before Missingness, rendered as in a look file. On the Phase 1 rows the co-read's pipeline-independent Δ equals the secondary read, +0.2941 on 7 PRs. The cost-matched Δ reads +0.0805 on the 7 pairs within the ±25 % tolerance.
- **Output tree.** `<out>/<label>/<batch>/<arm>/<task>-t<trial>/grade.json`, with each matched session's grade under `sessions/s<i>/grade.json`. Each label also gets `INDEX.json`, which holds the keys and their hashes, the frozen root's manifest digest, the re-pointed tasks, every grade's sha256, and the cells without a key. A copy of the frozen root's `MANIFEST.sha256` sits beside it. A determinism check re-grades a seeded sample of three cells from scratch and compares every file byte for byte (`CHECK.json`).

## Why this is a correction, not a design change

The three label-set sensitivities and the dominated wording are registered in §10 and §5. This addendum supplies the missing branch, the presentation label and the final's co-reads, and the procedure that makes the registered sensitivities computable without altering the record. No estimand, filter, boundary, seed or primary figure changes, and no model is called.
