# Task: the final read's sensitivity 'contaminated cells re-included' becomes a family — one read per contamination class, plus every class at once

`evals/analysis/c132/reads.py` reads the cycle-132 ablation. The primary read excludes every contaminated cell. The registered sensitivity `class9_nonrepo_egress_reincluded` re-reads the primary with the matched-bare cells whose ONLY invalidity is a class-9 egress contamination that named no repository (`common.contamination_detail(...)` = `network_egress:nonrepo`) counted valid, reporting `n_pairs`, `reincluded_keys`, `reincluded_cells` and `recall_matched`. The grader records many other contamination patterns on a row's `contaminated` dict (`outside_path`, `git_history`, `repo_name`, `suite_path`, … and patterns it has not seen yet).

**Bug (observed):** only the one class-9 non-repository class can be re-included; a cell contaminated by any other pattern is excluded from every read, so the final read cannot say what each class of contamination costs. `contamination_detail` reads a `network_egress` record that does not say whether a repository was named as `network_egress:repo`, as if it had.

**Expected:**
- `common.contamination_detail(*objs)` returns `network_egress:nonrepo` when `repo_named` is false, `network_egress:repo` when it is true, and `network_egress:unstated` when the record does not say; any other non-empty `pattern` is its own class; `unknown` when no object carries one. It still falls back from the row's record to the grade's.
- The registered sensitivity is the family `contaminated_reincluded_per_class` (`reincluded_family(cells, reg, seed)`): `observed` lists, sorted, every class seen on a contaminated cell (an unknown pattern is a class of its own); `classes[<class>]` is the primary re-read with the cells whose only invalidity is a contamination of that class counted valid (one such cell brings back one pair; each read carries `n_pairs`, `reincluded_keys` and `recall_matched`); `all_classes` re-includes every class at once; `counts` is `{arm: {group: {class: n}}}`. A contaminated cell with a second invalidity (an oracle exposure, say) never comes back. With no contaminated cell the family is `status` `no_contaminated_cells` with `observed` `[]`. In the sensitivities' `order` the family sits right after `degraded_contaminated_excluded`; the primary filter and `missingness` are unchanged.
- The legacy name `class9_nonrepo_egress_reincluded`, when registered, still produces its member: the `network_egress:nonrepo` read.
- `reads.md` describes each member (`re-included: network_egress:nonrepo`, `re-included: every class`, …) and lists the counts as `<arm> / <group>: <class> <n>, <class> <n>`.

Fix the bug in place and add a regression test of your own. Run the tests under `evals/analysis/c132/tests` that cover the code you change, with `python3 -m pytest -q <file>`.
