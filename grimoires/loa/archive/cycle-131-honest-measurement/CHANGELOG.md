Arm toggles `oracle_open` (eval-only within-pin A/B), `dissent: false` and `bare_model: fable`; `apply_eval_config_variant` writes the evaluation config (`config_variant: eval`). ### Changed

### Fixed

- **The closed mount refuses an unavailable fix commit** (PR #1286 Bridgebuilder F001, HIGH). `lib/sandbox-mount.sh overlay_answer_paths` exits 2 before writing anything when `fixture.yaml`'s `fix_commit` is not in the source tree: Sprint 263 logged `fix_commit_unavailable` and overlaid the PR paths only, which left the fix-only paths at the later copy while `check_mount_closed` called the mount closed. `check_mount_closed` and `took-effect.sh` rule `oracle_closed` now fail on `overlay_fix_commit=unavailable` as well. No recorded run was affected: `overlay_fix_commit=available` on all 18 closed-mount cycle-131 runs, `none` on the 4 whose fixture declares no fix commit.
- **Grader 1.3.1: the oracle detector scans error-marked tool results** (PR #1286 Bridgebuilder F002, MEDIUM). A differing `diff` exits 1 and Claude Code marks the result `is_error` with the output after an `Exit code 1` line; 1.3.0 skipped every such result. 1.3.1 strips the line and scans the rest: the diff form needs printed ranges near a planted site (no must_match-only credit), the read form later-only text, and an error-marked section without ranges is never `oracle_exposed_unknown` (a refusal or a hook block names the paths and prints no diff). Recall and contamination are unchanged. The 36 cycle-130 and 27 cycle-131 review-catch runs re-graded under 1.3.1 are identical on every oracle field, recall and contamination (63 of 63); the 26 error-marked results carrying diff ranges in those transcripts all compare `pr/base` with `pr/head` or read `head.diff`, never the mount copy. The pinned 1.3.0 rows remain the main read (DEC-0648); the 1.3.1 grades are a labelled sensitivity.
